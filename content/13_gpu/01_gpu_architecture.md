# Архитектура GPU и модель исполнения CUDA

Цель — понять, какие задачи подходят GPU, как работа распределяется между host и device и чем программная модель CUDA отличается от устройства конкретного процессора NVIDIA. Предварительно разберите [устройство компьютера](../12_computer_architecture/01_digital_foundations.md), [микроархитектуру CPU](../12_computer_architecture/04_cpu_microarchitecture.md) и [SIMD](../12_computer_architecture/10_simd_and_data_layout.md); общий маршрут приведён в [оглавлении](README.md).

## Лёгкий уровень

1. Какие особенности задачи позволяют ускорить её на GPU: много независимых элементов, повторяющиеся операции, большой объём данных или низкая задержка одного решения? Сравните обработку миллиона пикселей, поиск одного элемента в связном списке и обработку одиночного запроса пользователя; для каждого случая объясните, каких сведений ещё не хватает для выбора устройства.

   **Ответ:** GPU подходит для большого параллелизма и достаточного объёма работы на запуск. Миллион пикселей обычно даёт независимые вычисления; одиночный связный список содержит зависимые адреса; одиночный запрос может быть ограничен задержкой. Нужны стоимость операции, объём передач, зависимости, размер пакета и измерение полного времени.

   **Типичная ошибка:** Выбирать устройство только по числу элементов.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

2. Что обозначают host и device в CUDA и какую работу обычно выполняют CPU и GPU? Проследите путь массивов от подготовки на CPU до проверки результата после вычисления на дискретном GPU с отдельной памятью, отмечая вычисления и перемещения данных.

   **Ответ:** Host — CPU и управляющая сторона программы, device — выбранный GPU. CPU готовит входы, выделяет device-буферы, передаёт данные H2D, запускает kernel, ожидает зависимую работу, получает D2H и проверяет результат; device выполняет параллельную часть.

   **Типичная ошибка:** Читать host-результат до завершения D2H.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

3. Чем поток CUDA отличается от потока операционной системы на CPU? Объясните, что означает запуск большого числа логических потоков и почему миллион запущенных потоков не означает миллион независимо работающих аппаратных исполнителей в один момент.

   **Ответ:** CUDA thread — логический экземпляр kernel со своими индексами и состоянием; он планируется группами warp на SM. Поток ОС имеет иной контекст и планировщик. Миллион CUDA-потоков выполняется порциями в пределах доступных ресурсов, а не миллионом одновременных аппаратных исполнителей.

   **Типичная ошибка:** Сопоставлять CUDA thread одному ядру CPU.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

4. Что называют kernel и чем его запуск отличается от обычного вызова функции C++? Для покомпонентного сложения двух массивов укажите, какой код исполняет host, какой — device и какую часть задачи выполняет один поток.

   **Ответ:** Kernel — device-функция `__global__`, запускаемая с grid/block и stream; обычный launch асинхронен относительно CPU. Host выделяет и передаёт массивы, а поток device вычисляет один или несколько элементов суммы с проверкой границ.

   **Пример:** `size_t i = size_t(blockIdx.x)*blockDim.x + threadIdx.x; if (i<n) c[i]=a[i]+b[i];`

   **Типичная ошибка:** Считать возврат из launch завершением вычисления.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

5. Как связаны grid, thread block и thread в модели CUDA? Нарисуйте запуск из нескольких блоков и объясните, зачем программе нужны координаты блока и потока, если все потоки начинают выполнение одной функции.

   **Ответ:** Grid состоит из блоков, блок — из потоков. Индексы различают экземпляры одной функции и назначают им данные; блоки одного обычного запуска могут исполняться в произвольном порядке.

   **Пример:** `grid: [block 0: t0…t7] [block 1: t0…t7]`; глобальный индекс равен `8*blockIdx.x+threadIdx.x`.

   **Типичная ошибка:** Использовать только номер потока для всей сетки.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

6. Что такое streaming multiprocessor, или SM, в GPU NVIDIA? Разделите понятия SM, блока CUDA, warp и арифметического исполнительного устройства; объясните, почему число «CUDA cores» нельзя напрямую сравнивать с числом ядер CPU.

   **Ответ:** SM — аппаратный мультипроцессор, размещающий блоки и планирующий warp на исполнительные конвейеры. Блок — программная группа, warp — группа планирования потоков, арифметическое устройство исполняет определённые операции. CUDA core не обладает всеми возможностями самостоятельного CPU core, поэтому простое сравнение количества некорректно.

   **Типичная ошибка:** Считать блок и SM одним объектом.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

7. Что такое warp в CUDA NVIDIA и как в нём группируются потоки одного блока? Для блока из 96 потоков определите число warp при размере warp 32, затем объясните, почему это число нельзя без проверки переносить на программные модели других производителей.

   **Ответ:** Warp объединяет потоки одного блока по последовательным линейным номерам. При размере 32 блок из 96 потоков содержит 3 warp; неполный последний warp возможен при других размерах. Размер и семантика групп у других платформ проверяются отдельно.

   **Типичная ошибка:** Считать 32 универсальной константой для всех GPU.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

8. Чем SIMT отличается от SIMD на уровне того, как программист описывает вычисления? Сравните обработку массива скалярными потоками CUDA и векторной инструкцией CPU; отдельно объясните, что происходит с разными значениями данных и с разными направлениями условного перехода.

   **Ответ:** SIMT описывает скалярную программу каждого потока с отдельными индексами и данными; SIMD явно оперирует вектором lanes. Разные значения данных нормальны в обоих случаях. Разные ветви внутри warp требуют маскирования/раздельного исполнения путей; SIMD-программа также может использовать маски.

   **Типичная ошибка:** Принимать разные операнды за divergence.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

## Средний уровень

9. Как grid, который содержит больше блоков, чем GPU способен одновременно разместить, всё же выполняется целиком? Опишите различие между запущенными и резидентными блоками и объясните, почему нельзя закреплять смысл «первая фаза» за блоками с меньшим `blockIdx.x`.

   **Ответ:** Резидентны только блоки, для которых сейчас доступны потоки, регистры и shared memory. По завершении блоков ресурсы получают следующие; так выполняется вся сетка. Порядок `blockIdx` не задаёт фазы и не гарантирует порядок старта или завершения.

   **Типичная ошибка:** Строить зависимости по возрастанию номера блока.

   **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

10. Что означает независимость блоков при обычном запуске CUDA kernel? Рассмотрите программу, где блок 1 ждёт флаг от блока 0: какие предположения о порядке запуска и наличии ресурсов потребуется проверить, прежде чем считать такую схему корректной?

    **Ответ:** Обычные блоки должны допускать независимое исполнение в любом порядке. Ожидание блока 0 из блока 1 требует корректной атомарной публикации и отдельного доказательства прогресса: ожидающий блок может занимать ресурс, нужный производителю. Надёжная граница фаз — следующий kernel в том же stream.

    **Типичная ошибка:** Полагаться на то, что блок 0 обязательно стартует раньше.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

11. Каким образом переключение между готовыми warp помогает скрывать задержку обращения к памяти? Сравните ситуацию с большим числом независимых обращений и ситуацию, где адрес следующего чтения зависит от результата предыдущего; объясните, почему большое число потоков само по себе не устраняет зависимость.

    **Ответ:** Пока один warp ждёт память, SM может выдавать инструкции другого готового warp. Независимые обращения создают параллелизм памяти; pointer chasing сохраняет зависимость следующего адреса от предыдущего чтения. Дополнительные независимые цепочки помогают, но число потоков не сокращает саму последовательную цепь.

    **Типичная ошибка:** Путать скрытие задержки с уменьшением задержки одного чтения.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

12. Что называют расхождением ветвей, или divergence, внутри warp? Сравните условия `threadIdx.x % 2 == 0` и `threadIdx.x / 32 == 0` для одномерного блока из 128 потоков CUDA NVIDIA; объясните, где разные направления могут возникнуть внутри одного warp.

    **Ответ:** Divergence возникает, когда активные lanes одного warp идут по разным путям. Чётность `threadIdx.x` делит каждый полный warp пополам; `threadIdx.x/32==0` истинно для первого warp целиком и ложно для остальных трёх. Последнее условие не создаёт расхождения внутри warp.

    **Типичная ошибка:** Называть разные ветви разных warp внутриварповым divergence.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

13. Какие свойства относятся к модели CUDA, а какие зависят от compute capability и конкретного GPU? Для размера блока, числа SM, объёма памяти, поддерживаемых инструкций и аппаратных ограничений предложите способ проверки, не опирающийся на характеристики одного знакомого устройства.

    **Ответ:** Иерархия grid/block/thread — часть модели; допустимые размеры, число SM, память и инструкции зависят от GPU и compute capability. Используют `cudaGetDeviceProperties`, `cudaDeviceGetAttribute`, документацию архитектуры и атрибуты конкретного kernel, а затем проверяют launch.

    **Типичная ошибка:** Переносить предел размера блока с одного GPU на любой другой.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

14. Чем вычислительный kernel отличается от обработки вершины или фрагмента в графическом конвейере? Сравните назначение этапов, способ задания работы и представление результатов; объясните, почему наличие мощной графики ещё не отвечает на вопрос о скорости конкретной CUDA-программы.

    **Ответ:** Графические стадии обрабатывают вершины/фрагменты по контракту конвейера и формируют графические ресурсы. CUDA kernel получает явно заданную сетку и пишет произвольные разрешённые данные в память. Скорость зависит от нужных операций, памяти, передачи и библиотек, поэтому графический рейтинг недостаточен.

    **Типичная ошибка:** Оценивать CUDA-задачу только по FPS.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

15. Как накладные расходы запуска меняют выбор между CPU и GPU для маленьких задач? В учебной модели запуск занимает 8 мкс, вычисление на GPU — 2 мкс, а на CPU — 6 мкс; сравните выполнение одной задачи и объединение ста независимых задач в один запуск, явно указав допущения.

    **Ответ:** Одна задача на GPU занимает `8+2=10 мкс`, на CPU — `6 мкс`. Если сто задач имеют линейно складывающуюся GPU-работу и объединяются без дополнительных затрат, GPU требует `8+100*2=208 мкс`, CPU последовательно — `600 мкс`, выигрыш около 2,88 раза. Передачи и упаковка в модели отсутствуют.

    **Типичная ошибка:** Умножать накладные расходы одного объединённого запуска на сто.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

16. Почему ускорение самого kernel может слабо влиять на время всей операции? Рассчитайте выигрыш, если CPU-версия занимает 40 мс, а GPU-версия тратит 12 мс на ввод, 4 мс на kernel и 12 мс на возврат результата; затем оцените эффект сокращения времени kernel вдвое.

    **Ответ:** Полное время GPU равно `12+4+12=28 мс`, ускорение относительно CPU — `40/28≈1,43`. После сокращения kernel до 2 мс получается 26 мс и `40/26≈1,54`; улучшение самой GPU-версии лишь `28/26≈1,077`.

    **Типичная ошибка:** Объявлять двукратное ускорение приложения по времени kernel.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

## Сложный уровень

17. Как по графу зависимостей определить, какую часть алгоритма можно исполнить параллельно на GPU? Разберите обработку пакета изображений с независимым преобразованием пикселей, вычислением общей статистики и последующей нормализацией; обозначьте зависимости, которые мешают просто поручить все стадии независимым потокам одного обычного запуска.

    **Ответ:** Пиксельные преобразования независимы, общая статистика требует reduction, нормализация зависит от готовой статистики. Достаточная схема — преобразование, reduction в один или несколько запусков, нормализация с зависимостями в stream. Обычный блоковый барьер не завершает статистику всей сетки.

    **Типичная ошибка:** Объединять глобальные фазы без допустимой межблоковой синхронизации.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

18. Что меняется в рассуждениях о корректности при independent thread scheduling на поддерживающих его GPU NVIDIA? Объясните, почему соседство потоков в warp не заменяет явно требуемую синхронизацию и почему нельзя переносить выводы о прогрессе потоков между архитектурами без проверки модели исполнения.

    **Ответ:** Independent thread scheduling допускает более независимый прогресс потоков warp. Обмен через память требует `__syncwarp` с корректной маской либо более широкого барьера; коллективные операции требуют согласованного участия. Рассуждение «соседняя lane уже записала» само по себе не устанавливает порядок памяти.

    **Типичная ошибка:** Использовать неявную синхронность warp вместо протокола обмена.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

19. Всегда ли условный оператор в исходном CUDA C++ означает аппаратное расхождение ветвей? Предложите эксперимент с короткой и длинной ветвью, просмотром сгенерированного кода и замерами; укажите, как отличить предикацию, пропуск неактивных lanes и дополнительные вычисления от предположений по одному исходному тексту.

    **Ответ:** Компилятор может заменить короткую ветвь предикацией, удалить её или вычислить оба результата. Сравнивают короткую и длинную версии на одинаковых данных, изучают SASS и профиль активных lanes/ветвлений, измеряют время после прогрева. Вывод делают по реально исполняемым инструкциям.

    **Типичная ошибка:** Предсказывать машинную ветвь по одному `if` в C++.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

20. Как форма двумерного блока влияет на состав warp, если линейный номер потока внутри блока вычисляется с самым быстрым изменением координаты `x`? Для блоков `dim3(16, 16)` и `dim3(32, 8)` выпишите координаты первого warp и определите, как условие по чётности строки меняет распределение работы.

    **Ответ:** Линейный номер меняет x быстрее y. В `(16,16)` первый warp содержит `(x=0…15,y=0)` и `(x=0…15,y=1)`; в `(32,8)` — `(x=0…31,y=0)`. Чётность строки разделяет первый warp первого варианта, но постоянна внутри каждого warp второго.

    **Типичная ошибка:** Считать одну строку warp при любой ширине блока.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

21. Почему максимальное число резидентных потоков не гарантирует максимальную производительность? Сравните kernel с длинной цепочкой зависимых инструкций и kernel с несколькими независимыми вычислениями на поток; сформулируйте гипотезы о влиянии числа готовых warp, регистров и исполнительных конвейеров, которые затем можно проверить профилем.

    **Ответ:** Occupancy показывает заполнение, а не число полезно выдаваемых инструкций. Длинная зависимая цепь требует других готовых warp; независимые операции одного потока дают ILP, иногда ценой большего числа регистров и меньшей occupancy. Проверяют время, spills, причины ожиданий и загрузку конвейеров.

    **Типичная ошибка:** Максимизировать occupancy без проверки времени.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

22. Какие ограничения появляются при разделении одной задачи между несколькими GPU? Для независимых пакетов данных и для тесно связанных подзадач отдельно оцените роль баланса нагрузки, обмена промежуточными результатами и подготовки данных на CPU; объясните, почему удвоение числа GPU не даёт автоматического ускорения вдвое.

    **Ответ:** Независимые пакеты делят с учётом скорости GPU и входного потока CPU. Связанные части дополнительно требуют пересылки границ, коллективных операций и синхронизации; топология ограничивает обмен. Последовательная подготовка, дисбаланс и коммуникации мешают идеальному удвоению скорости.

    **Типичная ошибка:** Игнорировать стоимость обмена и дисбаланс устройств.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

23. Как количество арифметических операций на байт помогает предварительно оценить пригодность вычисления для GPU? Для преобразований с 2 и 200 операциями на элемент, читающих и записывающих по одному `float`, посчитайте интенсивность в учебной модели без повторного использования данных и объясните, какие аппаратные пределы потребуется сопоставить.

    **Ответ:** Один входной и один выходной `float` дают 8 полезных байт на элемент. Интенсивность равна `2/8=0,25` и `200/8=25` операций/байт. Сопоставляют с отношением вычислительного потолка к пропускной способности памяти; для offload отдельно добавляют канал CPU–GPU.

    **Типичная ошибка:** Использовать пиковые FLOPS без ограничения памяти.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).

24. Как составить обоснованный план переноса CPU-алгоритма на GPU до написания оптимизированного kernel? Выберите обработку изображений, моделирование частиц или поиск по графу и определите объём параллелизма, зависимости, размещение данных, минимальную проверку корректности и измерения, после которых решение об ускорении можно пересмотреть.

    **Ответ:** Для изображений сначала выделяют независимые пиксельные этапы и глобальную статистику, оценивают трафик и сохраняют промежуточные данные на GPU. Делают простой kernel и CPU-эталон, проверяют хвосты и численную ошибку, измеряют передачи, kernel и end-to-end на нескольких размерах. По результату выбирают дальнейшую оптимизацию или CPU.

    **Типичная ошибка:** Начинать с сложного тайлинга до проверки полезности переноса.

    **Источник:** [CUDA Programming Model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html); [Writing SIMT Kernels](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html).
