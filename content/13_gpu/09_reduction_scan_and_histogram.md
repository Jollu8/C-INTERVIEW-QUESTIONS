# Редукции, префиксные суммы и гистограммы

Цель — научиться строить коллективные алгоритмы из операций отдельных потоков и проверять их корректность на произвольных размерах. Предварительно разберите [индексацию ядер](03_kernels_and_indexing.md), [shared memory](05_shared_memory_and_resources.md) и [синхронизацию и атомарные операции](06_synchronization_and_atomics.md).

## Лёгкий уровень

1. Что называют редукцией и чем её результат отличается от результата поэлементного преобразования массива? Для суммы, минимума и логического «все элементы положительные» определите вход, выход и операцию объединения частичных результатов.

   **Ответ:** Редукция объединяет множество элементов в один результат. Для суммы операция +, для минимума min, для «все положительные» — AND предикатов x>0. Поэлементное преобразование обычно сохраняет число элементов и не требует объединения разных входов.

   **Типичная ошибка:** Путать N независимых преобразований с одним общим итогом.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

2. Зачем операции редукции нужны нейтральный элемент и правило обработки пустого входа? Выберите такие правила для суммы и максимума и объясните, что должно произойти при массиве из одного элемента.

   **Ответ:** Нейтральный элемент не меняет результат объединения: 0 для суммы, -∞ для максимума float без иной NaN-политики или минимальное значение целого типа. Пустой максимум можно вместо sentinel объявить отсутствующим значением. Для одного элемента возвращают его с учётом выбранной NaN-политики.

   **Типичная ошибка:** Возвращать 0 как максимум массива отрицательных чисел.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

3. Как дерево сложений распределяет суммирование восьми чисел между потоками? Нарисуйте этапы объединения и сравните число операций и длину цепочки зависимостей с последовательным суммированием.

   **Ответ:** Восемь значений объединяют попарно в 4 суммы, затем в 2 и в 1. Всего 7 сложений, глубина 3 против 7 зависимых сложений последовательного варианта. Перестройка дерева допустима по контракту операции и численной точности.

   **Типичная ошибка:** Принимать меньшую глубину за меньшее суммарное число сложений.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

4. Чем inclusive scan отличается от exclusive scan? Для массива `[3, 1, 4, 2]` выпишите оба результата с начальным значением ноль и объясните, как каждый выходной элемент связан с префиксом входа.

   **Ответ:** Inclusive включает текущий элемент: `[3,4,8,10]`; exclusive с нулём даёт `[0,3,4,8]`. Выход i равен сумме входов 0…i либо 0…i-1 соответственно.

   **Типичная ошибка:** Сдвигать результат, забыв начальное значение.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

5. Чем scan отличается от обычной редукции и почему одного итогового значения недостаточно для вычисления всех префиксов? Приведите пример задачи, в которой нужны смещения каждого элемента, а затем сформулируйте размер её выходного массива.

   **Ответ:** Reduction даёт один итог, scan — значение для каждого префикса, обычно N выходов. Смещения переменных записей требуют exclusive scan их длин: итоговая сумма не определяет начало каждой записи. Для полного массива границ часто добавляют ещё один конечный offset.

   **Типичная ошибка:** Использовать общий итог вместо индивидуальных смещений.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

6. Что показывает гистограмма и как значения входа сопоставляются её корзинам, или bins? Для байтового изображения определите число корзин, тип счётчика и ожидаемую сумму всех счётчиков.

   **Ответ:** Гистограмма считает число значений в каждой корзине. Для byte-изображения нужны 256 bins; счётчик выбирают так, чтобы вместить N. При учёте каждого пикселя ровно один раз сумма bins равна N.

   **Типичная ошибка:** Переполнять 32-битный счётчик на больших данных.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

7. Почему операция `histogram[value]++` может дать неверный результат при выполнении разными потоками? Разберите два потока с одинаковым значением и сформулируйте требование к обновлению общей корзины.

   **Ответ:** Два потока могут прочитать один старый count и записать одинаковый increment, потеряв одно обновление. Требуется atomicAdd либо приватные локальные счётчики с корректным последующим объединением.

   **Типичная ошибка:** Считать разные входные позиции гарантией разных выходных bins.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

8. Что означает compaction, то есть удаление элементов, не удовлетворяющих предикату? Для массива `[-2, 5, 0, 7, -1]` сформулируйте ожидаемый результат отбора положительных чисел и отдельно уточните требование к сохранению их порядка.

   **Ответ:** Compaction оставляет элементы с истинным предикатом. Для положительных чисел результат `[5,7]`; при стабильном отборе сохраняется исходный относительный порядок, при нестабильном контракт допускает перестановку. Нужны также итоговая длина и достаточная ёмкость выхода.

   **Типичная ошибка:** Проверять только длину, не состав и порядок результата.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

## Средний уровень

9. Как реализовать редукцию внутри одного блока через shared memory и барьеры? Опишите, кто записывает исходные значения, какие потоки объединяют пары и в какие моменты все участники обязаны дождаться остальных.

   **Ответ:** Каждый поток записывает своё значение в shared, затем общий барьер. На шагах дерева выбранные потоки объединяют пары, после каждого зависимого этапа нужен корректный барьер. Финальный результат пишет один поток; для общей операции сохраняют допустимый порядок аргументов.

   **Типичная ошибка:** Ставить барьер только среди потоков, выполняющих сложение.

   **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

10. Как изменить блочную редукцию для 173 элементов при 256 потоках? Объясните, какие значения должны участвовать вместо отсутствующих элементов и почему ранний выход части потоков может нарушить барьеры алгоритма.

    **Ответ:** 173 потока загружают вход, остальные 83 — нейтральное значение операции. Все требуемые участники проходят барьеры дерева из 256 позиций. Это сохраняет результат и не создаёт чтений неинициализированной shared memory.

    **Типичная ошибка:** Возвращаться до коллективной загрузки/барьеров для i>=173.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

11. Как построить редукцию массива, который обрабатывают тысячи блоков? Определите размер массива частичных результатов, последовательность запусков и условие завершения, явно указав способ упорядочить чтение результатов предыдущего этапа.

    **Ответ:** Каждый из B блоков пишет один частичный результат в массив размера B. Следующий kernel редуцирует его, при необходимости повторяя до одного значения. Запуски в одном stream либо связанные events задают готовность предыдущего этапа.

    **Типичная ошибка:** Пытаться завершить общую reduction блоковым барьером.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

12. Как в CUDA использовать обмен значениями через shuffle для редукции внутри warp? Для неполной группы участников объясните, как задаётся маска, какие исходные lanes допустимо читать и почему одного вызова `__activemask()` внутри ветки недостаточно для доказательства состава группы.

    **Ответ:** Полный warp объединяет регистровые значения через согласованные shuffle-шаги. Для хвоста маску получают в совместной точке, используют только результаты от участвующих lanes и проверяют источник каждого объединения. Произвольная активная маска внутри ветви не доказывает логический состав группы.

    **Типичная ошибка:** Считать full mask допустимой для любого неполного warp.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

13. Как объединить локальный scan каждого блока в scan всего массива? Разделите алгоритм на вычисление локальных префиксов, обработку итогов блоков и добавление смещений и проверьте схему на массиве, занимающем два полных блока и один неполный.

    **Ответ:** Сначала считают локальные префиксы и итоги блоков, затем exclusive scan итогов, затем добавляют каждому локальному результату offset своего блока. Для двух полных и одного неполного блока смещения равны 0, total0, total0+total1. Хвост не должен добавлять фиктивные значения.

    **Типичная ошибка:** Прибавлять inclusive scan итогов и дважды учитывать текущий блок.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

14. Как получить стабильную compaction через предикат, scan и расстановку выбранных элементов? Проследите значения флагов и выходных индексов для небольшого примера и объясните, откуда взять итоговую длину, включая случай, когда ни один элемент не выбран.

    **Ответ:** Для `[-2,5,0,7,-1]` флаги `[0,1,0,1,0]`, exclusive scan `[0,0,1,1,2]`; выбранные элементы записывают по индексам 0 и 1. Длина равна последнему prefix плюс последний flag; при N=0 или отсутствии выбранных — 0.

    **Типичная ошибка:** Использовать inclusive prefix непосредственно как нулевой индекс выхода.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

15. Как уменьшить конкуренцию при построении гистограммы с небольшим числом корзин? Сравните глобальные атомарные обновления с частными гистограммами блоков, оценив объём временной памяти и стоимость их последующего объединения.

    **Ответ:** Частная гистограмма блока уменьшает конкуренцию между блоками, затем bins объединяют. Для B блоков и H корзин полный временный массив требует `B*H*sizeof(counter)`; shared-вариант расходует ресурс блока. Выигрыш зависит от распределения, затрат инициализации и merge.

    **Типичная ошибка:** Игнорировать обнуление частных bins.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

16. Чем segmented reduce и segmented scan отличаются от операций над одним непрерывным диапазоном? Для сегментов, заданных смещениями `[0, 3, 3, 8]`, определите границы и ожидаемые размеры результатов, отдельно разобрав пустой сегмент и начальное значение каждого префикса.

    **Ответ:** Offsets `[0,3,3,8]` задают три сегмента: `[0,3)`, пустой `[3,3)`, `[3,8)`. Segmented reduce даёт 3 результата с правилом пустого сегмента; segmented scan даёт 8 значений и заново начинает префикс каждого сегмента с его initial value.

    **Типичная ошибка:** Продолжать сумму предыдущего сегмента через границу.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

## Сложный уровень

17. Какие преобразования дерева редукции разрешает ассоциативность, а какие дополнительно требуют коммутативности? Сравните целочисленную сумму без переполнения, конкатенацию последовательностей и сложение `float`, сформулировав допустимые перестановки и требования к результату.

    **Ответ:** Ассоциативность разрешает менять расстановку скобок, коммутативность — переставлять операнды. Целочисленная сумма без переполнения допускает оба; конкатенация — только скобки при сохранении порядка. Float-сумма не ассоциативна в машинной арифметике, поэтому нужен допуск или фиксированная схема.

    **Типичная ошибка:** Называть float reduction точной реализацией математической ассоциативности.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

18. Как построить редукцию `argmax`, возвращающую значение и исходный индекс? Задайте правила для одинаковых максимумов и NaN, затем проверьте, что объединение пар сохраняет выбранный контракт на всех этапах дерева.

    **Ответ:** Редуцируют пары (value,index), например выбирают большее значение, при равенстве меньший исходный индекс. NaN можно явно игнорировать, определив отдельно all-NaN, либо включить в полный порядок. Одна и та же детерминированная операция выбора применяется на всех этапах.

    **Типичная ошибка:** Оставлять tie-breaking зависимым от порядка выполнения блоков.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

19. Как проверить редукцию и scan на размерах `0`, `1`, около размера блока и больше диапазона 32-битного индекса? Составьте набор проверок типов индексов, размеров выделения, переполнения суммы и хвостов, различая математическую ошибку и ошибку адресации.

    **Ответ:** Проверяют N=0,1,B-1,B,B+1, несколько блоков и хвосты; отдельно тестируют 64-битные индексные формулы выше 2^32 без огромной allocation. Контролируют произведения размеров, тип сумм и count. CPU-эталон отделяет численную погрешность от пропусков/выходов за границы.

    **Типичная ошибка:** Проверять большую длину через переполнившийся int.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

20. Гистограмма быстра на равномерных данных, но замедляется, когда 99 % элементов попадают в одну корзину: как исследовать причину? Сравните распределение обновлений между потоками, warp и блоками и предложите несколько вариантов локального объединения с оценкой дополнительных операций и ресурсов.

    **Ответ:** При 99% в одном bin атомики сериализуются на одном адресе. Сравнивают per-warp объединение одинаковых ключей, приватные bins warp/блока и merge; измеряют число атомиков, shared, barriers и время. Равномерный вход оставляют контрольным, поскольку оптимизация может ухудшить его.

    **Типичная ошибка:** Делать вывод о гистограмме по одному распределению.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

21. Как обработать сегменты, один из которых содержит миллионы элементов, а остальные — от нуля до четырёх? Сравните назначение одного потока, одного warp и нескольких блоков на сегмент, объяснив баланс работы, объединение частичных результатов и сохранение границ сегментов.

    **Ответ:** Малые сегменты назначают потокам или группируют; длинный делят между warp/блоками с частичными итогами. Частичные результаты помечают сегментом и объединяют без пересечения границ. Проверяют overhead планирования и пустые сегменты, а не только суммарный N.

    **Типичная ошибка:** Назначать одинаковую группу каждому сегменту независимо от длины.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

22. Почему попытка организовать ожидание всех блоков обычного ядра через счётчик и цикл может зависнуть? Разберите ситуацию, когда ожидающие блоки занимают ресурсы устройства, а нужные им блоки ещё не запущены, и выберите документированный способ разделить этапы алгоритма.

    **Ответ:** Ожидающие резидентные блоки могут занять все ресурсы и не пустить ещё не стартовавших участников барьера. Используют отдельные kernels с stream-зависимостью либо документированный cooperative launch при выполнении его ограничений. Корректный atomic counter не доказывает прогресс.

    **Типичная ошибка:** Считать busy-wait полноценным grid barrier.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

23. Как определить, окупится ли объединение transform и reduce в одном проходе? Постройте оценку трафика для чтения `N` значений, записи временного массива и повторного чтения, затем сравните собственное ядро с подходящим примитивом CUB при одинаковом численном контракте.

    **Ответ:** Отдельный transform пишет N временных значений, reduce читает их: fusion убирает примерно `2*N*sizeof(intermediate)` байт и один launch. Вход всё равно читается; возможны дополнительные регистры и сложность reduction. Сравнивают с CUB на том же типе, операции и допуске, включая workspace.

    **Типичная ошибка:** Приписывать fusion устранение обязательного чтения входа.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

24. Реализуйте набор reduce, scan, histogram и compaction для нескольких размеров и распределений входа. Как вы подтвердите корректность относительно CPU и CUB, измерите стоимость временной памяти и объясните случаи, когда уменьшение числа запусков или атомарных операций не дало ускорения?

    **Ответ:** Эталонная схема: reduce — staged partials, scan — local/block totals/offsets, histogram — atomic bins или приватизация, compaction — flags/exclusive scan/scatter. Для каждого сравнивают с CPU/CUB N=0,1,хвосты, большие размеры и разные распределения. Отдельно сохраняют workspace, время всех этапов и численный контракт.

    **Типичная ошибка:** Считать уменьшение launch или atomics достаточным доказательством ускорения.

    **Источник:** [CUB API](https://nvidia.github.io/cccl/unstable/cub/api.html); [Warp Shuffle Functions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).

## Критерий освоения
