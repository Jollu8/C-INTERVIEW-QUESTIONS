# Шаблоны_и_метапрограммирование

Примеры — независимые фрагменты: объявления шаблонов размещаются на уровне пространства имён, вызовы и действия с объектами — внутри функции. Для краткости стандартные заголовки и `main` обычно опущены; подключайте заголовки используемых компонентов (`<type_traits>`, `<utility>`, `<concepts>`, `<array>`, `<vector>`, `<string>`, `<tuple>` и другие). Если не указано иное, примеры можно читать в контексте C++20. Намеренно ошибочные строки закомментированы. Ссылки на рабочий проект стандарта ведут на обновляемый текст, который может включать возможности более новых версий.

## Лёгкий уровень

1. Что такое шаблон в C++?

	**Ответ:** Шаблон описывает семейство функций, классов или переменных, зависящих от параметров. Конкретная специализация получается при подстановке аргументов.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	Box<int> b{42};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.pre](https://eel.is/c++draft/temp.pre)

2. Для чего нужны шаблоны?

	**Ответ:** Шаблоны позволяют описать общий алгоритм или структуру данных один раз, сохранив статическую проверку типов.

	**Пример:**

	```cpp
	template<class T> T twice(T x) { return x + x; }
	auto n = twice(3); // int, 6
	```

	**Источник:** [Рабочий проект стандарта C++: temp.pre](https://eel.is/c++draft/temp.pre)

3. Чем шаблон отличается от обычной функции?

	**Ответ:** Обычная функция имеет конкретную сигнатуру. Шаблон функции задаёт семейство функций, сигнатуры которых зависят от аргументов шаблона.

	**Пример:**

	```cpp
	int twice(int x) { return x + x; }
	template<class T> T twice_generic(T x) { return x + x; }
	```

	**Источник:** [Рабочий проект стандарта C++: temp.fct](https://eel.is/c++draft/temp.fct)

4. Чем шаблон класса отличается от обычного класса?

	**Ответ:** Обычный класс — конкретный тип; шаблон класса задаёт семейство типов. `Box<int>` и `Box<double>` — разные типы.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	Box<int> a{1};
	Box<double> b{2.5};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.class](https://eel.is/c++draft/temp.class)

5. Что такое обобщённое программирование?

	**Ответ:** Это написание алгоритмов через требования к операциям над типами, без привязки к одному конкретному типу. В C++ основной инструмент — шаблоны.

	**Пример:**

	```cpp
	template<class T> T square(T x) { return x * x; }
	auto s = square(1.5); // тип должен поддерживать умножение
	```

	**Источник:** [Рабочий проект стандарта C++: temp.fct](https://eel.is/c++draft/temp.fct)

6. Почему шаблоны уменьшают дублирование кода?

	**Ответ:** Изменяющаяся часть кода становится параметром, а общая логика остаётся в одном определении. При этом машинный код разных специализаций может дублироваться.

	**Пример:**

	```cpp
	template<class T> T negated(T x) { return -x; }
	auto a = negated(3);
	auto b = negated(2.5);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.pre](https://eel.is/c++draft/temp.pre)

7. Что такое параметр шаблона?

	**Ответ:** Параметр шаблона — имя типа, константного значения или шаблона, используемое в его определении и заменяемое аргументом.

	**Пример:**

	```cpp
	template<class T, int N> struct Buffer { T data[N]; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

8. Какие виды параметров шаблона существуют?

	**Ответ:** В C++20 есть параметры типов, нетиповые параметры и параметры-шаблоны; каждый из этих видов может образовывать пакет параметров.

	**Пример:**

	```cpp
	template<class T, int N, template<class> class C>
	struct Config { C<T> value; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

9. Что такое типовой параметр шаблона?

	**Ответ:** Это параметр, аргументом которого является тип. Его объявляют через `typename` или `class`.

	**Пример:**

	```cpp
	template<typename T> struct Box { T value; };
	Box<double> box{1.5};
	```

10. Что такое нетиповой параметр шаблона?

	**Ответ:** Это параметр, которому передают допустимое константное значение, а не тип. Значение участвует в идентичности специализации.

	**Пример:**

	```cpp

	Count<3> three; // Count<4> — другой тип
	```

11. Что такое шаблон функции?

	**Ответ:** Это определение семейства функций, параметризованного типами, значениями или другими шаблонами.

	**Пример:**

	```cpp
	template<class T> T identity(T x) { return x; }
	```

12. Как объявить шаблон функции?

	**Ответ:** Перед объявлением функции записывают `template<...>` со списком параметров; определение может следовать отдельно.

	**Пример:**

	```cpp
	template<class T> T identity(T x);
	template<class T> T identity(T x) { return x; }
	```

13. Что такое шаблон класса?

	**Ответ:** Это семейство классов, структура и поведение которых могут зависеть от аргументов шаблона.

	**Пример:**

	```cpp
	template<class T> struct Pair { T first, second; };
	```

14. Как объявить шаблон класса?

	**Ответ:** Перед объявлением `class` или `struct` указывают список параметров шаблона.

	**Пример:**


15. Что означает `template<typename T>`?

	**Ответ:** Запись объявляет один параметр типа с именем `T`. Внутри шаблона `T` обозначает подставленный тип.

	**Пример:**

	```cpp
	template<typename T> T zero() { return T{}; }
	auto x = zero<int>();
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

16. Чем `typename` отличается от `class` в параметрах шаблона?

	**Ответ:** Для объявления параметра типа эти ключевые слова равнозначны: `class` не ограничивает аргумент классами. В других контекстах, например перед зависимым типом, они не взаимозаменяемы.

	**Пример:**

	```cpp
	template<class T> struct A {};
	template<typename T> struct B {};
	A<int> a; B<int> b;
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

17. Что такое инстанцирование шаблона?

	**Ответ:** Инстанцирование — получение специализации из шаблона с конкретными аргументами и проверка необходимых частей её определения. Это не обязательно означает генерацию отдельного машинного кода.

	**Пример:**

	```cpp
	template<class T> T twice(T x) { return x + x; }
	int n = twice(2); // инстанцируется twice<int>
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

18. Когда компилятор создаёт конкретную версию шаблона?

	**Ответ:** Неявное инстанцирование происходит, когда контекст требует определения: например, при вызове функции или создании объекта полного типа. Одного указателя на специализацию класса обычно недостаточно.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	Box<int>* p = nullptr; // определение класса пока не требуется
	Box<int> b{1};         // требуется полный тип
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

19. Что такое аргумент шаблона?

	**Ответ:** Аргумент — конкретный тип, значение или шаблон, подставляемый вместо параметра; он может быть указан явно, выведен или взят по умолчанию.

	**Пример:**

	```cpp
	template<class T, int N> struct Buffer {};
	Buffer<int, 8> b; // аргументы: int и 8
	```

	**Источник:** [Рабочий проект стандарта C++: temp.arg](https://eel.is/c++draft/temp.arg)

20. Чем параметр шаблона отличается от аргумента шаблона?

	**Ответ:** Параметр объявляется в определении шаблона, аргумент передаётся при его использовании. Это аналогично различию параметров и аргументов обычной функции.

	**Пример:**

	```cpp
	template<class T> struct Box {}; // T — параметр
	Box<int> b;                      // int — аргумент
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

21. Можно ли вызвать шаблонную функцию без явного указания типа?

	**Ответ:** Да, если недостающие аргументы можно вывести из аргументов вызова либо получить из значений по умолчанию.

	**Пример:**

	```cpp
	template<class T> T identity(T x) { return x; }
	auto n = identity(42); // T = int
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.call](https://eel.is/c++draft/temp.deduct.call)

22. Что такое вывод аргументов шаблона?

	**Ответ:** Это определение аргументов шаблона по сопоставлению параметризованных типов с известными типами выражений. Оно подчиняется специальным правилам, а не перебору любых неявных преобразований.

	**Пример:**

	```cpp
	template<class T> void inspect(const T&) {}
	inspect(3.5); // T = double
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct](https://eel.is/c++draft/temp.deduct)

23. Когда компилятор сам выводит тип `T`?

	**Ответ:** Когда `T` встречается в выводимом контексте параметров функции и сопоставление даёт непротиворечивый результат.

	**Пример:**

	```cpp
	template<class T> void pair_of(T, T) {}
	pair_of(1, 2); // T = int
	// pair_of(1, 2.0); // противоречие: int и double
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.call](https://eel.is/c++draft/temp.deduct.call)

24. Когда тип шаблона приходится указывать явно?

	**Ответ:** Когда параметр не выводится, например встречается только в возвращаемом типе, либо когда нужно выбрать конкретную специализацию и разрешить преобразование аргументов.

	**Пример:**

	```cpp
	template<class T> T make_zero() { return T{}; }
	auto n = make_zero<int>();
	```

	**Источник:** [Рабочий проект стандарта C++: temp.arg.explicit](https://eel.is/c++draft/temp.arg.explicit)

25. Что такое `T` в шаблоне `template<typename T>`?

	**Ответ:** `T` — произвольное имя параметра типа, а не специальное ключевое слово. Вместо него можно использовать более содержательное имя.

	**Пример:**

	```cpp
	template<typename Element> struct Box { Element value; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

26. Можно ли использовать шаблон с `int`, `double`, `std::string`?

	**Ответ:** Да, если операции используемой специализации допустимы для выбранного типа. Наличие шаблона не делает любую операцию универсальной.

	**Пример:**

	```cpp
	template<class T> T twice(T x) { return x + x; }
	auto a = twice(2);
	auto b = twice(1.5);
	auto c = twice(std::string{"ab"}); // "abab"
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

27. Что такое универсальная функция `max` в виде шаблона?

	**Ответ:** Это функция, сравнивающая два значения одного выводимого типа. Простой вариант возвращает копию большего значения; ему нужны сравнение и возможность копирования результата.

	**Пример:**

	```cpp
	template<class T> T max_value(T a, T b) { return a < b ? b : a; }
	auto n = max_value(3, 7);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.fct](https://eel.is/c++draft/temp.fct)

28. Почему шаблон функции удобен для одинаковой логики над разными типами?

	**Ответ:** Тип параметризуется, а порядок действий остаётся общим. Исправление алгоритма в одном определении применяется ко всем его специализациям.

	**Пример:**

	```cpp
	template<class T> T smaller(T a, T b) { return b < a ? b : a; }
	auto x = smaller(2, 4);
	auto y = smaller(2.5, 4.5);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.fct](https://eel.is/c++draft/temp.fct)

29. Что такое шаблонный класс `Box<T>`?

	**Ответ:** Это пользовательское семейство классов-обёрток: `T` определяет тип хранимого значения. Само имя `Box` не обозначает стандартный контейнер.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	Box<std::string> b{"hello"};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.class](https://eel.is/c++draft/temp.class)

30. Как создать объект шаблонного класса?

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	Box<int> b{42};
	```

31. Что такое специализация шаблона?

	**Ответ:** Специализация — конкретный вариант шаблона. Она может быть получена инстанцированием или задана явно отдельным определением.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	template<> struct Box<bool> { bool value; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec](https://eel.is/c++draft/temp.spec)

32. Что такое полная специализация?

	**Ответ:** Полная явная специализация задаёт отдельное определение для конкретного набора всех аргументов шаблона.

	**Пример:**

	```cpp
	template<class T> struct Info { static constexpr int code = 0; };
	template<> struct Info<int> { static constexpr int code = 1; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.expl.spec](https://eel.is/c++draft/temp.expl.spec)

33. Что такое частичная специализация?

	**Ответ:** Частичная специализация задаёт реализацию для группы аргументов, удовлетворяющих шаблонному образцу. Она доступна шаблонам классов и переменных, но не функций.

	**Пример:**

	```cpp
	template<class T> struct Info {};
	template<class T> struct Info<T*> { using pointee = T; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec.partial](https://eel.is/c++draft/temp.spec.partial)

34. Можно ли частично специализировать шаблон функции?

	**Ответ:** Нет. Для функций используют перегрузку, ограничения или делегирование шаблонному классу с частичной специализацией.

	**Пример:**

	```cpp
	template<class T> void inspect(T) {}
	template<class T> void inspect(T*) {} // перегрузка, не специализация
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec.partial](https://eel.is/c++draft/temp.spec.partial)

35. Почему шаблоны функций обычно перегружают, а не частично специализируют?

	**Ответ:** Частичная специализация функций запрещена языком. Перегрузки позволяют выделить семейство аргументов, например все указатели, и участвуют в выборе вызываемой функции.

	**Пример:**

	```cpp
	template<class T> int kind(T) { return 0; }
	template<class T> int kind(T*) { return 1; }
	int x = 0; int k = kind(&x); // 1
	```

	**Источник:** [Рабочий проект стандарта C++: temp.func.order](https://eel.is/c++draft/temp.func.order)

36. Что такое перегрузка шаблонов?

	**Ответ:** Это несколько шаблонов функций с одним именем и различающимися списками параметров или допустимыми ограничениями.

	**Пример:**

	```cpp
	template<class T> void f(T) {}
	template<class T> void f(T, T) {}
	f(1); f(1, 2);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.over.link](https://eel.is/c++draft/temp.over.link)

37. Чем перегрузка шаблонов отличается от специализации?

	**Ответ:** Перегрузка добавляет отдельного кандидата при разрешении вызова. Явная специализация функции относится к уже выбранному первичному шаблону и не является независимой перегрузкой.

	**Пример:**

	```cpp
	template<class T> int f(T) { return 0; }
	template<> int f<int>(int) { return 1; }
	int f(double) { return 2; } // отдельная перегрузка
	```

	**Источник:** [Рабочий проект стандарта C++: temp.over](https://eel.is/c++draft/temp.over)

38. Что такое шаблонный метод внутри класса?

	**Ответ:** Это функция-член со своим списком параметров шаблона. Её параметры могут быть независимы от параметров содержащего класса.

	**Пример:**

	```cpp
	struct Printer {
	    template<class T> T echo(T x) { return x; }
	};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.mem](https://eel.is/c++draft/temp.mem)

39. Может ли обычный класс содержать шаблонный метод?

	**Ответ:** Да. Для шаблонной функции-члена сам класс не обязан быть шаблоном.

	**Пример:**

	```cpp
	struct Converter {
	    template<class T> T zero() { return T{}; }
	};
	auto n = Converter{}.zero<int>();
	```

	**Источник:** [Рабочий проект стандарта C++: temp.mem](https://eel.is/c++draft/temp.mem)

40. Может ли шаблонный класс содержать обычные методы?

	**Ответ:** Да. Обычный метод не имеет собственного списка параметров шаблона, но может использовать параметры класса.

	**Пример:**

79. Когда частичная специализация удобнее полной?

80. Что такое специализация для указателей, например `Box<T*>`?

81. Что такое специализация для ссылок?

	**Ответ:** Это частичная специализация по образцу ссылки. Для lvalue- и rvalue-ссылок можно задать разные варианты.

82. Что такое специализация для массивов?

	```cpp
	template<class T> struct Extent;
	```

83. Что такое шаблонный конструктор?

	**Ответ:** Это конструктор со своим списком параметров шаблона, позволяющий создавать объект из разных типов аргументов.

	**Пример:**

	```cpp
	struct Number {
	    double value;
	    template<class T> explicit Number(T x) : value(x) {}
	};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.mem](https://eel.is/c++draft/temp.mem)

84. Чем шаблонный конструктор отличается от обычного?

	**Ответ:** Он описывает семейство конструкторов, а обычный конструктор имеет фиксированную сигнатуру. Шаблонный конструктор сам по себе не считается специальным копирующим или перемещающим конструктором.

	**Пример:**

	```cpp
	struct X {
	    X(const X&) = default;
	    template<class T> explicit X(const T&) {}
	};
	```

	**Источник:** [Рабочий проект стандарта C++: class.copy.ctor](https://eel.is/c++draft/class.copy.ctor)

85. Может ли шаблонный конструктор мешать неявно сгенерированным операциям копирования?

	**Ответ:** Да: он не подавляет автоматическое объявление копирующего конструктора сам по себе, но может выиграть разрешение перегрузки, особенно с forwarding reference. Его обычно ограничивают, исключая собственный тип.

	**Пример:**

	```cpp
	struct X {
	    X() = default;
	    X(const X&) = default;
	    template<class T> requires (!std::same_as<std::remove_cvref_t<T>, X>)
	    explicit X(T&&) {}
	};
	```

87. Для чего нужна class template argument deduction?

88. Что такое CTAD?

92. Для чего нужны шаблоны с переменным числом параметров?

93. Что такое пакет параметров шаблона?

94. Как выглядит `template<typename... Ts>`?

	```cpp
	template<typename... Ts> struct Types {
	```

95. Что такое распаковка пакета параметров?

	**Ответ:** Распаковка `pattern...` повторяет образец для каждого элемента пакета в допустимом контексте, например списке аргументов.

	```cpp
	template<class... Ts> auto pack(Ts... xs) {
	```

96. Где используют variadic templates?

	**Пример:**

	```cpp
	template<class... Args> auto make_tuple_copy(Args... args) {
	```

97. Что такое `sizeof...(Ts)`?

	**Ответ:** Это оператор, возвращающий число элементов пакета как константное значение типа `std::size_t`. Он не вычисляет значения элементов.

	**Пример:**

	```cpp
	template<class... Ts> constexpr auto count = sizeof...(Ts);
	static_assert(count<int, double> == 2);
	```

	**Источник:** [Рабочий проект стандарта C++: expr.sizeof](https://eel.is/c++draft/expr.sizeof)

98. Что такое fold expression?

	**Ответ:** Fold expression, или выражение свёртки, применяет бинарный оператор ко всему пакету. Доступно с C++17; скобки являются частью синтаксиса.

	**Пример:**

	```cpp
	template<class... Ts> auto sum(Ts... xs) { return (0 + ... + xs); }
	auto n = sum(1, 2, 3); // 6
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.fold](https://eel.is/c++draft/expr.prim.fold)

99. Для чего fold expressions нужны в метапрограммировании и generic-коде?

	**Ответ:** Свёртки компактно выражают суммирование, последовательные действия и логические условия по пакету. Начальное значение определяет в том числе поведение пустого пакета.

	**Пример:**

	```cpp
	template<class... Ts> constexpr bool all_integral = (std::is_integral_v<Ts> && ...);
	static_assert(all_integral<int, long>);
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.fold](https://eel.is/c++draft/expr.prim.fold)

100. Чем fold expression удобнее ручной рекурсии по пакету параметров?

	**Ответ:** Они убирают отдельный базовый случай и рекурсивные перегрузки. Нужно учитывать направление свёртки, особенно для неассоциативных операторов.

	**Пример:**

	```cpp
	template<class... Ts> auto sum(Ts... xs) { return (0 + ... + xs); }
	auto empty = sum(); // 0, без отдельной перегрузки
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.fold](https://eel.is/c++draft/expr.prim.fold)

101. Что такое метапрограммирование в C++?

	**Ответ:** Метапрограммирование — вычисление свойств, типов и структуры программы средствами самого языка. В C++ для этого используют шаблоны, traits, `constexpr` и concepts.

102. Почему шаблоны исторически стали инструментом метапрограммирования?

103. Что такое template metaprogramming?

	**Ответ:** TMP — метапрограммирование на шаблонах: входами служат аргументы шаблона, результатами — типы, константы или выбранные реализации.

	**Пример:**

	```cpp
	template<class T> struct AddPointer { using type = T*; };
	```

104. Что означает “вычисление на этапе компиляции”?

	**Ответ:** Это получение результата при трансляции, без необходимости выполнять соответствующее вычисление во время работы программы. Константный контекст требует такого результата.

	**Пример:**

	```cpp

	std::array<int, n> values{};
	```

	**Источник:** [Рабочий проект стандарта C++: expr.const](https://eel.is/c++draft/expr.const)

105. Чем вычисления на этапе компиляции отличаются от вычислений во время выполнения?

	**Ответ:** Во время компиляции доступны только данные и операции, допустимые в константном вычислении; runtime может использовать ввод пользователя и внешние ресурсы.

	**Пример:**

	```cpp
	constexpr int fixed = 5 * 5;

	int dynamic = n * n;
	```

106. Зачем выполнять часть логики на этапе компиляции?

	**Ответ:** Чтобы заранее проверить инварианты, построить таблицы и убрать повторяющуюся работу из исполнения. Пользу сопоставляют со стоимостью сборки.

	**Пример:**

	```cpp
	constexpr std::array<int, 3> squares{1, 4, 9};

	```

107. Какие плюсы даёт метапрограммирование?

119. Что такое type traits?

	**Пример:**

	```cpp
	static_assert(std::is_pointer_v<int*>);
	using T = std::remove_pointer_t<int*>;
	```

	**Источник:** [Рабочий проект стандарта C++: meta](https://eel.is/c++draft/meta)

120. Для чего нужны type traits?

	**Ответ:** Они позволяют ограничивать шаблоны, выбирать ветви алгоритма и нормализовать типы без создания объектов этих типов.

	**Пример:**

	```cpp
	template<class T> void check() { static_assert(std::is_integral_v<T>); }
	check<int>();
	```

	**Источник:** [Рабочий проект стандарта C++: meta.unary.cat](https://eel.is/c++draft/meta.unary.cat)

121. Что делает `std::is_same`?

	**Ответ:** Проверяет точное совпадение двух типов, включая ссылки и cv-квалификаторы.

	**Пример:**

	```cpp
	static_assert(std::is_same_v<int, int>);
	static_assert(!std::is_same_v<int, const int>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.rel](https://eel.is/c++draft/meta.rel)

122. Что делает `std::is_integral`?

	**Ответ:** Проверяет, является ли тип целочисленным, включая `bool` и символьные типы. Перечисления и ссылки к ним не относятся.

	**Пример:**

	```cpp
	static_assert(std::is_integral_v<const int>);
	static_assert(!std::is_integral_v<int&>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.unary.cat](https://eel.is/c++draft/meta.unary.cat)

123. Что делает `std::is_pointer`?

	**Ответ:** Проверяет, является ли тип указателем на объект или функцию. Указатели на члены и `std::nullptr_t` сюда не входят.

	**Пример:**

	```cpp
	static_assert(std::is_pointer_v<int*>);
	static_assert(!std::is_pointer_v<std::nullptr_t>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.unary.cat](https://eel.is/c++draft/meta.unary.cat)

124. Что делает `std::is_reference`?

	**Ответ:** Проверяет, является ли тип lvalue- или rvalue-ссылкой.

	**Пример:**

	```cpp
	static_assert(std::is_reference_v<int&>);
	static_assert(std::is_reference_v<int&&>);
	static_assert(!std::is_reference_v<int>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.unary.comp](https://eel.is/c++draft/meta.unary.comp)

125. Что делает `std::is_const`?

	**Ответ:** Проверяет `const` на верхнем уровне типа. Константность объекта по указателю не делает сам указатель константным; ссылочные типы тоже не являются const-квалифицированными.

	**Пример:**

	```cpp
	static_assert(std::is_const_v<int* const>);
	static_assert(!std::is_const_v<const int*>);
	static_assert(!std::is_const_v<const int&>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.unary.prop](https://eel.is/c++draft/meta.unary.prop)

126. Что делает `std::remove_reference`?

	**Ответ:** Удаляет верхнеуровневую ссылку, сохраняя остальные свойства типа, включая `const`.

	**Пример:**

	```cpp
	using T = std::remove_reference_t<const int&>;
	static_assert(std::is_same_v<T, const int>);
	```

127. Что делает `std::remove_const`?

	**Ответ:** Удаляет верхнеуровневый `const`, но не снимает ссылки и не меняет константность типа, на который указывает указатель.

	**Пример:**

	```cpp
	static_assert(std::is_same_v<std::remove_const_t<const int>, int>);
	static_assert(std::is_same_v<std::remove_const_t<const int*>, const int*>);
	```

128. Что делает `std::decay`?

	**Ответ:** Выполняет преобразование, похожее на передачу по значению: снимает ссылку, превращает массивы и функции в указатели, иначе удаляет верхнеуровневые cv-квалификаторы.

	**Пример:**

	```cpp
	static_assert(std::is_same_v<std::decay_t<const int&>, int>);
	static_assert(std::is_same_v<std::decay_t<int[3]>, int*>);
	```

129. Что делает `std::conditional`?

	**Ответ:** Выбирает один из двух типов по константному булеву условию. Оба переданных аргумента-типа должны быть корректно образованы.

	**Пример:**

	```cpp
	using T = std::conditional_t<true, int, double>;
	```

130. Что делает `std::enable_if`?

	**Ответ:** При истинном условии содержит псевдоним `type`, иначе такого члена нет. В непосредственном контексте подстановки это используют для SFINAE.

	**Пример:**

	```cpp
	template<class T> std::enable_if_t<std::is_integral_v<T>, T>
	inc(T x) { return x + 1; }
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

131. Почему `type traits` считаются основой TMP?

	**Ответ:** Traits предоставляют строительные блоки для решений на основе типов: предикаты, преобразования и константы. Из них составляют более сложные ограничения и метафункции.

	**Пример:**

	```cpp
	template<class T> using Value = std::remove_cv_t<std::remove_reference_t<T>>;
	```

132. Что такое alias `std::enable_if_t`?

	**Пример:**

	```cpp
	template<class T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
	```

133. Что такое alias `std::conditional_t`?

	**Ответ:** Это сокращение `typename std::conditional<B, T, F>::type`, выбирающее `T` при истинном `B`, иначе `F`; доступно с C++14.

	**Пример:**

	```cpp
	using Storage = std::conditional_t<(sizeof(int) > 2), int, long>;
	```

134. Что такое alias `std::remove_reference_t`?

135. Почему суффикс `_t` удобен в type traits?

	**Ответ:** Псевдонимы с `_t` сразу обозначают результирующий тип и убирают многословное `typename ...::type` в зависимом коде.


136. Что такое суффикс `_v` в современных traits?

	**Ответ:** Обычно это variable template, предоставляющий значение trait без `::value`. Большинство стандартных вариантов `_v` доступны с C++17.

	**Пример:**

	```cpp
	constexpr bool same = std::is_same_v<int, int>;
	```

	**Источник:** [Рабочий проект стандарта C++: meta.type.synop](https://eel.is/c++draft/meta.type.synop)

137. Чем `std::is_same<T,U>::value` отличается от `std::is_same_v<T,U>`?

	**Ответ:** Они дают одинаковое булево значение. Форма с `::value` обращается к члену класса trait, а `_v` — к вспомогательному шаблону переменной C++17.

	**Пример:**

	```cpp
	static_assert(std::is_same<int, int>::value == std::is_same_v<int, int>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.rel](https://eel.is/c++draft/meta.rel)

138. Что такое `constexpr`?

	**Ответ:** `constexpr` у переменной требует константной инициализации; у функции разрешает использование в константных вычислениях при выполнении условий. Обычный вызов такой функции не обязан вычисляться при компиляции.

	**Пример:**

	```cpp
	constexpr int square(int x) { return x * x; }
	constexpr int n = square(4); // обязательно константное вычисление
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.constexpr](https://eel.is/c++draft/dcl.constexpr)

139. Чем `constexpr` отличается от шаблонного TMP?

	**Ответ:** `constexpr` позволяет вычислять значения обычными выражениями, циклами и функциями; классическое TMP кодирует вычисление через инстанцирование типов. Эти механизмы можно сочетать.

	**Пример:**

	```cpp
	constexpr int square(int x) { return x * x; }
	std::array<int, square(3)> data{};
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.constexpr](https://eel.is/c++draft/dcl.constexpr)

140. Когда `constexpr` удобнее TMP через классы?

	**Ответ:** Когда результатом является значение и алгоритм естественно выражается обычным кодом: арифметика, поиск, обработка таблиц. Для изменения структуры типов шаблоны остаются необходимы.

	**Пример:**

	```cpp
	constexpr int sum_to(int n) { int s = 0; for (int i = 1; i <= n; ++i) s += i; return s; }
	static_assert(sum_to(4) == 10);
	```

	**Источник:** [Рабочий проект стандарта C++: expr.const](https://eel.is/c++draft/expr.const)

141. Что такое `consteval` и как он связан с вычислениями времени компиляции?

	**Ответ:** `consteval` объявляет immediate function: обычный потенциально вычисляемый вызов должен давать константное выражение. Это средство C++20 для обязательного выполнения при компиляции.

	**Пример:**

	```cpp
	consteval int square(int x) { return x * x; }
	int n = square(4); // вызов вычислен при компиляции
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.constexpr](https://eel.is/c++draft/dcl.constexpr)

142. Что такое `if constexpr`?

	**Ответ:** `if constexpr` выбирает ветвь по константному условию. В шаблоне отброшенная ветвь не инстанцируется, когда условие после подстановки перестаёт зависеть от параметров; доступно с C++17.

	**Пример:**

	```cpp
	template<class T> auto value(T x) {
	    if constexpr (std::is_pointer_v<T>) return *x;
	    else return x;
	}
	```

	**Источник:** [Рабочий проект стандарта C++: stmt.if](https://eel.is/c++draft/stmt.if)

143. Чем `if constexpr` отличается от обычного `if`?

	**Ответ:** Обычный `if` не избавляет от проверки обеих ветвей для конкретной специализации. `if constexpr` позволяет отбросить зависимый код неподходящей ветви, но не отключает синтаксический разбор.

	**Пример:**

	```cpp
	template<class T> int get(T x) {
	    if constexpr (std::is_pointer_v<T>) return *x;
	    else return x;
	}
	int n = get(3);
	```

	**Источник:** [Рабочий проект стандарта C++: stmt.if](https://eel.is/c++draft/stmt.if)

144. Почему `if constexpr` сильно упростил шаблонный код?

	**Ответ:** Разные варианты реализации можно выразить внутри одной функции, без вспомогательных перегрузок и классов. Ограничения допустимости вызова всё равно лучше задавать на интерфейсе, если это существенно.

	**Пример:**

	```cpp
	template<class T> auto size_or_one(const T& x) {
	    if constexpr (requires { x.size(); }) return x.size();
	    else return std::size_t{1};
	}
	```

	**Источник:** [Рабочий проект стандарта C++: stmt.if](https://eel.is/c++draft/stmt.if)

145. Что такое `decltype`?

	**Ответ:** `decltype` получает тип выражения без его вычисления. Для непомещённого в скобки имени берётся объявленный тип, для других выражений учитывается категория значения.

	**Пример:**

	```cpp
	int x = 0;
	static_assert(std::is_same_v<decltype(x), int>);
	static_assert(std::is_same_v<decltype((x)), int&>);
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.type.decltype](https://eel.is/c++draft/dcl.type.decltype)

146. Что такое `decltype(auto)`?

	**Ответ:** Начиная с C++14, `decltype(auto)` выводит тип по правилам `decltype`, сохраняя ссылки, когда это следует из выражения. Скобки вокруг возвращаемого имени могут изменить результат.

	**Пример:**

	```cpp
	int x = 1;
	decltype(auto) ref = (x); // int&
	ref = 2;
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.spec.auto](https://eel.is/c++draft/dcl.spec.auto)

147. Чем `auto` и `decltype` полезны в шаблонном коде?

	**Ответ:** `auto` избавляет от ручной записи выводимого типа, а `decltype` позволяет выразить тип результата операции над параметрами. Это особенно полезно при разных входных типах.

	**Пример:**

	```cpp
	template<class T, class U>
	auto add(T a, U b) -> decltype(a + b) { return a + b; }
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.type.decltype](https://eel.is/c++draft/dcl.type.decltype)

148. Что такое `std::declval`?

	**Ответ:** `std::declval<T>()` из `<utility>` предоставляет выражение типа `std::add_rvalue_reference_t<T>` для анализа, не создавая объект. Его нельзя реально вычислять.

	**Пример:**

	```cpp
	using R = decltype(std::declval<std::string&>().size());
	```

149. Для чего используется `std::declval` в метапрограммировании?

	**Ответ:** Он позволяет исследовать операции над типами, даже если объект нельзя создать конструктором по умолчанию или вообще нельзя создавать, например абстрактный класс.

	**Пример:**

	```cpp
	struct X { X() = delete; int size() const; };
	```

150. Почему `std::declval` полезен только в невычисляемом контексте?

	**Ответ:** Это вспомогательное объявление для анализа выражений, а не функция с реализацией для runtime. Вычисляемое использование нарушает требования библиотеки.

	**Пример:**

## Выше среднего уровня

151. Что такое SFINAE?

	**Ответ:** SFINAE — правило, по которому некоторые ошибки подстановки в непосредственном контексте объявления шаблона исключают кандидата из рассмотрения, вместо немедленной ошибки всей программы. Ошибки в теле функции этим правилом обычно не покрываются.

	**Пример:**

	```cpp
	template<class T> auto f(T x) -> decltype(x.size()) { return x.size(); }
	int f(...) { return 0; }
	auto n = f(42); // первая перегрузка исключена
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

152. Как расшифровывается SFINAE?

	**Ответ:** Substitution Failure Is Not An Error — «неудача подстановки не является ошибкой». Это правило действует в определённых контекстах подстановки, а не для любых ошибок шаблонного кода.

	**Пример:**

	```cpp
	template<class T> typename T::value_type probe(T);
	void probe(...);
	using R = decltype(probe(1)); // void
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

153. В чём основная идея SFINAE?

	**Ответ:** Компилятор пробует сформировать кандидатов; неподходящая подстановка может убрать один из них, позволяя выбрать другой. Если подходящих кандидатов не осталось, вызов всё же ошибочен.

	**Пример:**

	```cpp
	template<class T> auto probe(T x) -> decltype(x.size());
	int probe(...);
	using R = decltype(probe(7)); // int
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

154. Почему ошибка при подстановке аргументов шаблона иногда не считается ошибкой компиляции?

	**Ответ:** Потому что ошибка в непосредственном контексте подстановки рассматривается как неприменимость кандидата. Ошибка внутри отдельно инстанцированного класса или тела функции может остаться жёсткой ошибкой.

	**Пример:**

	```cpp
	template<class T> auto f(T x) -> decltype(x.run());
	void f(...);
	using R = decltype(f(1)); // fallback
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

155. Как SFINAE влияет на выбор перегрузки?

	**Ответ:** SFINAE отбрасывает кандидатов до окончательного выбора лучшей перегрузки. Само по себе оно не назначает оставшимся кандидатам приоритет.

	**Пример:**

	```cpp
	template<class T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
	int kind(T) { return 1; }
	int kind(...) { return 0; }
	int n = kind(1.5); // 0
	```

	**Источник:** [Рабочий проект стандарта C++: temp.over](https://eel.is/c++draft/temp.over)

156. Что такое substitution failure?

	**Ответ:** Это неудача формирования типа или выражения при подстановке аргументов, например обращение к отсутствующему вложенному типу. Для SFINAE важен непосредственный контекст этой ошибки.

	**Пример:**

	```cpp
	template<class T> typename T::value_type f(T);
	// Подстановка T = int не может образовать int::value_type.
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

157. Где используют SFINAE на практике?

	**Ответ:** Для условного включения перегрузок, обнаружения операций и адаптации библиотечных интерфейсов до C++20. В новом коде ограничения часто проще выразить concepts.

	**Пример:**

	```cpp
	template<class T> auto length(const T& x) -> decltype(x.size()) {
	    return x.size();
	}
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

158. Как `std::enable_if` помогает реализовать SFINAE?

	**Ответ:** Если условие ложно, у `enable_if` нет `type`; использование этого члена в непосредственном контексте делает подстановку неудачной.

	**Пример:**

	```cpp
	template<class T> std::enable_if_t<std::is_integral_v<T>, T>
	next(T x) { return x + 1; }
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

159. Что такое SFINAE в возвращаемом типе функции?

	**Ответ:** Условие или проверяемое выражение помещают в возвращаемый тип. При неудачной подстановке соответствующий кандидат исключается.

	**Пример:**

	```cpp
	template<class T> auto size_of(const T& x) -> decltype(x.size()) {
	    return x.size();
	}
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

160. Что такое SFINAE в списке параметров?

	**Ответ:** Проверку включают в тип параметра функции, нередко дополнительного параметра со значением по умолчанию.

	**Пример:**

	```cpp
	template<class T> void accept(T, std::enable_if_t<std::is_integral_v<T>>* = nullptr) {}
	accept(3);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

161. Что такое SFINAE через дополнительный шаблонный параметр?

	**Ответ:** Добавляют параметр шаблона, тип которого существует только при выполнении условия. Для перегрузок удобен нетиповой параметр: одних разных значений по умолчанию у типового параметра недостаточно для разных объявлений.

	**Пример:**

	```cpp
	template<class T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
	void accept(T) {}
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.general](https://eel.is/c++draft/temp.deduct.general)

162. Почему SFINAE может делать код трудночитаемым?

	**Ответ:** Проверка требований смешивается с технической записью возвращаемых типов и дополнительных параметров. Именованные traits или concepts делают назначение ограничения яснее.

	**Пример:**

	```cpp
	template<std::integral T> void accept(T) {} // C++20: условие видно сразу
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr](https://eel.is/c++draft/temp.constr)

163. Что такое detection idiom?

	**Ответ:** Detection idiom — шаблонный приём проверки корректности типа или выражения через SFINAE, обычно с `std::void_t`. Результатом служит trait, а проверяемая операция не выполняется.

	**Пример:**

	```cpp
	template<class T, class = void> struct HasSize : std::false_type {};
	template<class T> struct HasSize<T, std::void_t<decltype(std::declval<T&>().size())>> : std::true_type {};
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

164. Для чего нужен detection idiom?

	**Ответ:** Чтобы безопасно выбрать реализацию по наличию операции, не вызывая её и не создавая объект. Проверка синтаксической допустимости не доказывает семантическую корректность операции.

	**Пример:**

	```cpp
	template<class T> concept HasSize = requires(T& x) { x.size(); };
	static_assert(HasSize<std::string>); // современная форма обнаружения
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req](https://eel.is/c++draft/expr.prim.req)

165. Как проверить существование вложенного типа с помощью метапрограммирования?

	**Ответ:** Первичный trait возвращает `false`, а частичная специализация с `void_t<typename T::value_type>` выбирается при существовании доступного вложенного типа.

	**Пример:**

	```cpp
	template<class T, class = void> struct HasValue : std::false_type {};
	template<class T> struct HasValue<T, std::void_t<typename T::value_type>> : std::true_type {};
	static_assert(HasValue<std::vector<int>>::value);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

166. Как проверить существование метода у типа на этапе компиляции?

	**Ответ:** Проверяют корректность выражения вызова на нужной категории объекта. Например, проверка на `const T&` требует доступного вызова именно у константного объекта.

	**Пример:**

	```cpp
	template<class T> concept HasSize = requires(const T& x) { x.size(); };
	static_assert(HasSize<std::string>);
	```

167. Что такое `void_t`?

	**Ответ:** `std::void_t<Ts...>` — alias template C++17, который для корректного набора аргументов обозначает `void`. Некорректные аргументы могут вызвать SFINAE при подстановке.

	**Пример:**

	```cpp
	static_assert(std::is_same_v<std::void_t<int, double>, void>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

168. Как `std::void_t` помогает в detection idiom?

	**Ответ:** Он сводит успешную проверку выражений к типу `void`, совпадающему с параметром первичного trait. Если проверка не удалась, частичная специализация не подходит.

	**Пример:**

	```cpp
	template<class T, class = void> struct HasType : std::false_type {};
	template<class T> struct HasType<T, std::void_t<typename T::type>> : std::true_type {};
	```

169. Почему `void_t` сильно упростил шаблонную интроспекцию?

	```cpp
	template<class T, class = void> struct HasPairTypes : std::false_type {};
	```

170. Что такое идиома “обнаружения” свойств типа?

	**Ответ:** Это получение булева свойства «выражение или тип допустимы» через подстановку. Начиная с C++20 ту же задачу часто решает `requires`-выражение.

	**Пример:**

	```cpp
	template<class T> concept Incrementable = requires(T& x) { ++x; };
	```

171. Как проверить, поддерживает ли тип оператор `+`?

	**Ответ:** Проверяют выражение `a + b` на нужных типах и категориях значений. При необходимости дополнительно ограничивают тип результата.

	**Пример:**

	```cpp
	template<class T> concept Addable = requires(const T& a, const T& b) { a + b; };
	```

172. Как проверить, есть ли у типа `begin()` и `end()`?

	**Ответ:** Для методов проверяют `x.begin()` и `x.end()`. Если требуется полноценный диапазон, предпочтительнее `std::ranges::range`, учитывающий и поддерживаемые свободные функции.

	**Пример:**

	```cpp
	template<class T> concept HasMembers = requires(T& x) { x.begin(); x.end(); };
	```

173. Что такое перегрузка на основе свойств типов?

	**Ответ:** Это выбор функции по статическим свойствам аргументов с помощью constraints, SFINAE или tag dispatch.

	**Пример:**

	```cpp
	void process(std::integral auto) {}
	void process(std::floating_point auto) {}
	process(3); process(1.5);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr](https://eel.is/c++draft/temp.constr)

174. Что такое tag dispatch?

	**Ответ:** Tag dispatch — передача дополнительного объекта-тега, тип которого выбирает нужную перегрузку. Тег выражает известное при компиляции свойство.

	**Пример:**

	```cpp
	int impl(std::true_type) { return 1; }
	int impl(std::false_type) { return 0; }
	template<class T> int kind(T) { return impl(std::is_integral<T>{}); }
	```

	**Источник:** [Рабочий проект стандарта C++: over.match](https://eel.is/c++draft/over.match)

175. Для чего нужен tag dispatch?

	**Ответ:** Он отделяет выбор алгоритма от его реализаций и позволяет использовать иерархию тегов, например категории итераторов.

	**Пример:**

	```cpp
	void impl(std::random_access_iterator_tag) {}
	void impl(std::input_iterator_tag) {}
	template<class It> void run(It) { impl(typename std::iterator_traits<It>::iterator_category{}); }
	```

	**Источник:** [Рабочий проект стандарта C++: iterator.tags](https://eel.is/c++draft/iterator.tags)

176. Чем tag dispatch отличается от SFINAE?

	**Ответ:** Tag dispatch выбирает перегрузку по типу дополнительного аргумента. SFINAE исключает кандидата из-за неудачной подстановки; дополнительный аргумент-тег не требуется.

	**Пример:**

	```cpp
	int choose(std::true_type) { return 1; }
	int choose(std::false_type) { return 0; }
	int n = choose(std::is_pointer<int*>{});
	```

	**Источник:** [Рабочий проект стандарта C++: over.match](https://eel.is/c++draft/over.match)

177. Когда tag dispatch удобнее, чем `enable_if`?

	**Ответ:** Когда нужно разделить внутренние реализации по небольшому набору категорий или использовать наследование тегов. Для ограничения публичного интерфейса concepts обычно выразительнее.

	**Пример:**

	```cpp
	void save_impl(std::true_type) {}
	void save_impl(std::false_type) {}

	```

178. Что такое `std::true_type` и `std::false_type` как теги dispatch?

	**Ответ:** Это два разных типа, представляющих булев результат. Передав объект одного из них, можно выбрать перегрузку без runtime-ветвления.

	**Пример:**

	```cpp
	constexpr int pick(std::true_type) { return 10; }
	constexpr int pick(std::false_type) { return 20; }
	```

179. Что такое compile-time branching?

	**Ответ:** Это выбор типа или реализации по информации времени компиляции. Для специализации шаблона ненужный зависимый код может вообще не инстанцироваться.

	**Пример:**

	```cpp
	template<class T> auto read(T x) {
	    if constexpr (std::is_pointer_v<T>) return *x;
	    else return x;
	```

180. Какие способы ветвления на этапе компиляции существуют в современном C++?

	**Ответ:** Используют специализации, перегрузки с constraints или SFINAE, tag dispatch, `if constexpr` и выбор типов через traits. `if consteval` C++23 отдельно различает контекст константного вычисления.

181. Чем `if constexpr` отличается от специализации?

	**Ответ:** `if constexpr` выбирает инструкции внутри функции; специализация может заменить целый класс, его структуру и интерфейс либо определение функции для конкретных аргументов.

	**Пример:**

	```cpp
	template<class T> struct Box { T value; };
	```

182. Когда лучше использовать специализацию, а когда `if constexpr`?

	**Ответ:** `if constexpr` удобен для небольшого различия алгоритмов с общим интерфейсом. Специализация подходит, если меняются представление данных, набор членов или принципиально вся реализация.

	**Пример:**

	```cpp
	template<class T> struct Storage { T value; };
	```

188. Что такое instantiation depth?

	**Ответ:** Code bloat — избыточный объём сгенерированного кода, например из-за множества почти одинаковых специализаций. Вынос независимой от типа работы в обычную функцию может уменьшить повторение.

194. Почему множество инстанцирований шаблонов может приводить к раздутому коду?

	**Ответ:** Каждая комбинация аргументов обозначает отдельную специализацию; если её код нужен и не объединён, он занимает место. Особенно быстро число вариантов растёт при нескольких независимых параметрах.

195. Что такое explicit instantiation?

	**Ответ:** Явное инстанцирование предписывает получить специализацию из существующего шаблона. Определение записывают с `template`, а объявление `extern template` подавляет соответствующее неявное инстанцирование в предусмотренных правилами случаях.

	**Пример:**

	```cpp
	template<class T> T twice(T x) { return x + x; }
	template int twice<int>(int);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.explicit](https://eel.is/c++draft/temp.explicit)

196. Когда explicit instantiation может быть полезна?

	**Ответ:** Когда набор типов известен заранее и хочется централизовать генерацию специализаций в одном `.cpp`. `extern template` в заголовке может уменьшить повторную работу, но не отменяет все проверки классов.

	**Пример:**

	```cpp
	// header.hpp
	template<class T> T twice(T);
	extern template int twice<int>(int);
	// В одном .cpp после определения twice: template int twice<int>(int);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.explicit](https://eel.is/c++draft/temp.explicit)

197. Что такое explicit specialization?

	**Ответ:** Это отдельное определение для конкретного набора аргументов, начинающееся с `template<>`. Оно заменяет поведение первичного шаблона для этого случая.

	**Пример:**

	```cpp
	template<class T> int code() { return 0; }
	template<> int code<int>() { return 1; }
	```

	**Источник:** [Рабочий проект стандарта C++: temp.expl.spec](https://eel.is/c++draft/temp.expl.spec)

198. Что такое implicit instantiation?

	**Ответ:** Это инстанцирование по необходимости без специального указания программиста, например при вызове шаблонной функции с выведенными аргументами.

	**Пример:**

	```cpp
	template<class T> T twice(T x) { return x + x; }
	int n = twice(3); // неявное инстанцирование twice<int>
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

199. Чем явное инстанцирование отличается от специализации?

	**Ответ:** Явное инстанцирование использует существующую реализацию шаблона, а явная специализация задаёт другую реализацию для выбранных аргументов.

	**Пример:**

	```cpp
	template<class T> int code() { return 0; }
	template int code<double>(); // исходная реализация
	template<> int code<int>() { return 1; } // новая реализация
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec](https://eel.is/c++draft/temp.spec)

200. Когда шаблонный код становится слишком сложным и требует упрощения?

	**Ответ:** Когда требования трудно понять, диагностика не указывает причину, а новые варианты требуют непропорционально сложных traits. Практический подход — именовать ограничения и оставлять обычную логику обычными функциями.

	**Пример:**

	```cpp
	template<std::integral T> T increment(T x) { return x + 1; }
	// Одно явно выраженное требование вместо цепочки enable_if.
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr](https://eel.is/c++draft/temp.constr)


## Сложный уровень

201. Что такое концепты в C++?

	**Ответ:** Concept — именованное условие времени компиляции для аргументов шаблона. Concepts появились в C++20 и позволяют явно описывать требования к интерфейсу.

	**Пример:**

	```cpp
	template<class T> concept HasSize = requires(const T& x) { x.size(); };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.concept](https://eel.is/c++draft/temp.concept)

202. Для чего были добавлены concepts?

	**Ответ:** Они позволяют выразить контракт шаблона в его объявлении, исключать неподходящие кандидаты и выбирать более специализированные интерфейсы по ограничениям.

	**Пример:**

	```cpp
	template<std::integral T> T remainder(T a, T b) { return a % b; }
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr](https://eel.is/c++draft/temp.constr)

203. Чем concepts лучше SFINAE с точки зрения читаемости?

	**Ответ:** Требование записывается как понятное булево условие, а не как искусственная ошибка подстановки. Имя concept можно повторно использовать в других интерфейсах.

	**Пример:**

	```cpp
	template<std::integral T> void consume(T) {} // вместо enable_if
	```

	**Источник:** [Рабочий проект стандарта C++: temp.concept](https://eel.is/c++draft/temp.concept)

204. Как объявить concept?

	**Ответ:** На уровне пространства имён пишут `template<...> concept Имя = условие;`. Условие должно давать константное значение типа `bool`.

	**Пример:**

	```cpp
	template<class T> concept Small = (sizeof(T) <= 8);
	static_assert(Small<char>);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.concept](https://eel.is/c++draft/temp.concept)

205. Что такое `requires`-выражение?

	**Ответ:** Это выражение типа `bool`, проверяющее допустимость заданных типов и операций без их выполнения. В зависимом шаблонном контексте неудача проверки обычно даёт `false`.

	**Пример:**

	```cpp
	template<class T> concept Addable = requires(T a, T b) { a + b; };
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req](https://eel.is/c++draft/expr.prim.req)

206. Что такое `requires`-clause?

	**Ответ:** Это часть объявления с ограничением применимости шаблона или функции-члена шаблона. В отличие от requires-expression, она присоединяет условие к объявлению.

	**Пример:**

	```cpp
	template<class T> requires std::integral<T>
	T twice(T x) { return x + x; }
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.decl](https://eel.is/c++draft/temp.constr.decl)

207. Как ограничить шаблон с помощью concept?

	**Ответ:** Concept можно указать вместо `typename`, в requires-clause или перед `auto` в сокращённом шаблоне функции.

	**Пример:**

	```cpp
	template<std::integral T> T square(T x) { return x * x; }
	int n = square(3);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.param](https://eel.is/c++draft/temp.param)

208. Что такое стандартный concept `std::integral`?

	**Ответ:** `std::integral<T>` из `<concepts>` проверяет `std::is_integral_v<T>`. Он включает `bool` и символьные типы, но не перечисления или ссылки.

	**Пример:**

	```cpp
	static_assert(std::integral<int>);
	static_assert(!std::integral<int&>);
	```

	**Источник:** [Рабочий проект стандарта C++: concepts.arithmetic](https://eel.is/c++draft/concepts.arithmetic)

209. Что такое стандартный concept `std::same_as`?

	**Ответ:** `std::same_as<T, U>` требует точного совпадения типов. Его определение обеспечивает симметричное поведение при упорядочивании ограничений.

	**Пример:**

	```cpp
	static_assert(std::same_as<int, int>);
	static_assert(!std::same_as<int, const int>);
	```

	**Источник:** [Рабочий проект стандарта C++: concept.same](https://eel.is/c++draft/concept.same)

210. Что такое стандартный concept `std::convertible_to`?

	**Ответ:** `std::convertible_to<From, To>` проверяет допустимость неявного преобразования и `static_cast`; дополнительно требует согласованности их результатов. Эти семантические требования не полностью проверяются компилятором.

	**Пример:**

	```cpp
	static_assert(std::convertible_to<int, double>);
	```

	**Источник:** [Рабочий проект стандарта C++: concept.convertible](https://eel.is/c++draft/concept.convertible)

211. Что такое стандартный concept `std::invocable`?

	**Ответ:** `std::invocable<F, Args...>` требует допустимости вызова по правилам `std::invoke`. В отличие от `regular_invocable`, не требует сохранять аргументы и давать равные результаты при равных входах.

	**Пример:**

	```cpp
	static_assert(std::invocable<decltype([](int x) { return x + 1; }), int>);
	```

	**Источник:** [Рабочий проект стандарта C++: concept.invocable](https://eel.is/c++draft/concept.invocable)

212. Что такое constrained templates?

	**Ответ:** Это шаблоны с явно заданными ограничениями. При неудовлетворённых associated constraints специализация функции не становится подходящим кандидатом.

	**Пример:**

	```cpp
	template<class T> requires (sizeof(T) <= 8)
	void accept(T) {}
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr](https://eel.is/c++draft/temp.constr)

213. Почему constrained templates дают лучшие сообщения об ошибках?

	**Ответ:** Проверка требований происходит на границе интерфейса, поэтому компилятор может указать нарушенный concept или выражение. Конкретное качество сообщения зависит от реализации компилятора.

	**Пример:**

	```cpp
	template<std::integral T> void accept(T) {}
	// accept(1.5); // не выполнено std::integral<double>
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.constr](https://eel.is/c++draft/temp.constr.constr)

214. Чем concept отличается от type trait?

	**Ответ:** Trait — обычно шаблон класса или переменной со свойством либо типом-результатом. Concept — специальная конструкция языка для ограничений, участвующая в их нормализации и упорядочивании.

	**Пример:**

	```cpp
	template<class T> concept Pointer = std::is_pointer_v<T>;
	static_assert(Pointer<int*>);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.concept](https://eel.is/c++draft/temp.concept)

215. Можно ли строить concept на основе traits?

	**Ответ:** Да: булевы traits могут быть частью выражения concept. Это позволяет дать имя составному условию.

	**Пример:**

	```cpp
	template<class T> concept Plain = std::is_trivially_copyable_v<T> && std::is_standard_layout_v<T>;
	static_assert(Plain<int>);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.concept](https://eel.is/c++draft/temp.concept)

216. Что такое subsumption в concepts?

	**Ответ:** Subsumption — отношение между нормализованными ограничениями, позволяющее определить более ограниченный вариант. Оно основано на идентичности атомарных ограничений, а не на произвольном доказательстве логической эквивалентности.

	**Пример:**

	```cpp
	template<class T> concept A = std::integral<T>;
	template<class T> concept B = A<T> && std::signed_integral<T>;
	template<A T> int f(T) { return 1; }
	template<B T> int f(T) { return 2; }
	int n = f(1); // 2
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.order](https://eel.is/c++draft/temp.constr.order)

217. Как concepts влияют на выбор перегрузки?

	**Ответ:** Они отбрасывают неподходящие кандидаты и при прочих соответствующих условиях позволяют предпочесть более ограниченный шаблон. Несвязанные ограничения всё ещё могут дать неоднозначность.

	**Пример:**

	```cpp
	template<std::integral T> int f(T) { return 1; }
	template<std::signed_integral T> int f(T) { return 2; }
	int n = f(1); // signed_integral уточняет integral
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.order](https://eel.is/c++draft/temp.constr.order)

218. Что такое переупорядочивание шаблонных перегрузок по ограничениям?

	**Ответ:** Точнее говорить о частичном упорядочивании: при выборе между подходящими шаблонами учитывается отношение их ограничений. Порядок записей в исходном файле приоритет не задаёт.

	**Пример:**

	```cpp
	template<class T> void f(T) {}
	template<std::integral T> void f(T) {}
	f(42); // ограниченный вариант
	```

	**Источник:** [Рабочий проект стандарта C++: temp.func.order](https://eel.is/c++draft/temp.func.order)

219. Почему две перегрузки с разными concepts могут выбирать разную реализацию?

	**Ответ:** Для каждого типа проверяется свой набор ограничений; затем применяются правила перегрузки и subsumption. Разные concepts не гарантируют однозначности, если их области пересекаются без отношения порядка.

	**Пример:**

	```cpp
	int kind(std::integral auto) { return 1; }
	int kind(std::floating_point auto) { return 2; }
	int a = kind(1), b = kind(1.5);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.order](https://eel.is/c++draft/temp.constr.order)

220. Что такое abbreviated function templates?

	**Ответ:** Это шаблоны функций C++20, где параметры шаблона неявно вводятся через `auto` в списке параметров функции. Каждое такое `auto` обычно задаёт отдельный параметр типа.

	**Пример:**

	```cpp
	auto add(auto a, auto b) { return a + b; }
	auto x = add(1, 2.5);
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.fct](https://eel.is/c++draft/dcl.fct)

221. Что означает запись вроде `std::integral auto x`?

	**Ответ:** Запись объявляет параметр с выводимым типом, который должен удовлетворять `std::integral`. Для функции это сокращённое объявление ограниченного шаблона.

	**Пример:**

	```cpp
	auto twice(std::integral auto x) { return x + x; }
	auto n = twice(4);
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.spec.auto](https://eel.is/c++draft/dcl.spec.auto)

222. Когда abbreviated templates удобны?

	**Ответ:** Для коротких generic-функций, когда имена параметров типов не нужны для сложных связей. Если два параметра должны иметь один тип, явный параметр `T` может быть понятнее.

	**Пример:**

	```cpp
	auto square(std::integral auto x) { return x * x; }
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.fct](https://eel.is/c++draft/dcl.fct)

223. Что такое `requires` после сигнатуры функции?

	**Ответ:** Это trailing requires-clause — ограничение после декларатора. Оно может ссылаться на параметры функции в невычисляемых проверках.

	**Пример:**

	```cpp
	template<class T> auto size_of(const T& x)
	    requires requires { x.size(); }
	{ return x.size(); }
	```

	**Источник:** [Рабочий проект стандарта C++: temp.constr.decl](https://eel.is/c++draft/temp.constr.decl)

224. Как проверить набор операций в `requires`-выражении?

	**Ответ:** Внутри блока перечисляют требования к выражениям, типам и дополнительным условиям. Все перечисленные требования должны выполняться.

	**Пример:**

	```cpp
	template<class T> concept Sequence = requires(T& x) {
	    typename T::value_type;
	    x.begin();
	    x.end();
	};
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req](https://eel.is/c++draft/expr.prim.req)

225. Что такое nested requirements в concepts?

	**Ответ:** Nested requirement имеет вид `requires условие;` внутри requires-expression и требует истинности константного условия, а не только его синтаксической корректности.

	**Пример:**

	```cpp
	template<class T> concept Small = requires {
	    requires (sizeof(T) <= 8);
	};
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req.nested](https://eel.is/c++draft/expr.prim.req.nested)

226. Что такое compound requirements?

	**Ответ:** Compound requirement проверяет выражение, при необходимости его `noexcept` и ограничение на `decltype((выражение))` результата.

	**Пример:**

	```cpp
	template<class T> concept Sized = requires(const T& x) {
	    { x.size() } noexcept -> std::same_as<std::size_t>;
	};
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req.compound](https://eel.is/c++draft/expr.prim.req.compound)

227. Что такое simple requirements?

	**Ответ:** Simple requirement — выражение с точкой с запятой. Оно проверяет только допустимость выражения, не выполняет его и не требует истинности его значения.

	**Пример:**

	```cpp
	template<class T> concept Addable = requires(T a) { a + a; };
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req.simple](https://eel.is/c++draft/expr.prim.req.simple)

228. Что такое type requirements?

	**Ответ:** Type requirement начинается с `typename` и проверяет, что указанное имя обозначает допустимый тип. Полнота именуемого класса сама по себе не требуется.

	**Пример:**

	```cpp
	template<class T> concept HasValue = requires { typename T::value_type; };
	```

	**Источник:** [Рабочий проект стандарта C++: expr.prim.req.type](https://eel.is/c++draft/expr.prim.req.type)

229. Чем concepts меняют стиль написания generic-кода?

	**Ответ:** Требования становятся частью интерфейса, получают имена и повторно используются. Это помогает строить алгоритмы по минимально нужным возможностям типов, а не по списку конкретных классов.

	**Пример:**

	```cpp
	template<std::ranges::input_range R> void scan(R&& range) {
	    for (auto&& value : range) { (void)value; }
	}
	```

	**Источник:** [Рабочий проект стандарта C++: range.req](https://eel.is/c++draft/range.req)

230. Что такое шаблонная рекурсия по типам?

	**Ответ:** Это последовательная обработка типов, например головы пакета и оставшегося хвоста. Пустой список или одиночный тип служит базовым случаем.

	**Пример:**

	```cpp
	template<class... Ts> struct Count;
	template<> struct Count<> : std::integral_constant<int, 0> {};
	template<class T, class... Ts> struct Count<T, Ts...> : std::integral_constant<int, 1 + Count<Ts...>::value> {};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.variadic](https://eel.is/c++draft/temp.variadic)

231. Что такое typelist?

	**Ответ:** Typelist — представление последовательности типов без обязательного хранения значений. Обычно это пустой шаблонный класс с пакетом типов.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	using List = Types<int, double, char>;
	```

	**Источник:** [Рабочий проект стандарта C++: temp.variadic](https://eel.is/c++draft/temp.variadic)

232. Зачем нужны typelist в метапрограммировании?

	**Ответ:** Он позволяет передавать и преобразовывать наборы типов: выбирать альтернативы, строить интерфейсы или регистрировать обработчики при компиляции.

	**Пример:**

	```cpp
	template<class... Ts> struct Types { static constexpr auto size = sizeof...(Ts); };
	using Inputs = Types<int, std::string>;
	static_assert(Inputs::size == 2);
	```

	**Источник:** [Рабочий проект стандарта C++: temp.variadic](https://eel.is/c++draft/temp.variadic)

233. Как представить список типов в виде шаблона?

	**Ответ:** Самая простая форма — пустой класс с пакетом параметров типов. Метаданные хранятся в аргументах специализации.

	**Пример:**

	```cpp
	template<typename... Ts> struct TypeList {};
	using Empty = TypeList<>;
	using Values = TypeList<int, float>;
	```

	**Источник:** [Рабочий проект стандарта C++: temp.variadic](https://eel.is/c++draft/temp.variadic)

234. Что такое операция `front` для typelist?

	**Ответ:** `front` извлекает первый тип списка. Для пустого списка нужно отдельно определить поведение либо считать операцию недопустимой.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	```

235. Что такое операция `push_front` для typelist?

	**Ответ:** `push_front` строит новый список, добавляя тип перед существующими элементами. Исходный тип списка не изменяется.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	template<class T, class L> struct PushFront;
	template<class T, class... Ts> struct PushFront<T, Types<Ts...>> { using type = Types<T, Ts...>; };
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec.partial](https://eel.is/c++draft/temp.spec.partial)

236. Что такое операция `push_back` для typelist?

	**Ответ:** `push_back` строит новый список с дополнительным типом в конце.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	template<class L, class T> struct PushBack;
	template<class... Ts, class T> struct PushBack<Types<Ts...>, T> { using type = Types<Ts..., T>; };
	```

237. Что такое операция `transform` над typelist?

	**Ответ:** `transform` применяет преобразование к каждому типу, сохраняя порядок и количество элементов.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	template<class L> struct Pointers;
	template<class... Ts> struct Pointers<Types<Ts...>> { using type = Types<Ts*...>; };
	using R = Pointers<Types<int, double>>::type;
	```

	**Источник:** [Рабочий проект стандарта C++: temp.variadic](https://eel.is/c++draft/temp.variadic)

238. Что такое операция `filter` над typelist?

	**Ответ:** `filter` оставляет типы, удовлетворяющие предикату, сохраняя их порядок. Это можно выразить рекурсией и условным добавлением головы списка.

	**Пример:**

	```cpp
	template<class... Ts> struct Types {};
	template<class T, class L> struct Prepend;
	template<class T, class... Ts> struct Prepend<T, Types<Ts...>> { using type = Types<T, Ts...>; };
	template<class... Ts> struct Filter;
	template<> struct Filter<> { using type = Types<>; };
	template<class T, class... Ts> struct Filter<T, Ts...> {
	    using tail = typename Filter<Ts...>::type;
	    using type = std::conditional_t<std::is_integral_v<T>, typename Prepend<T, tail>::type, tail>;
	};
	using R = Filter<int, double, char>::type; // Types<int, char>
	```

	**Источник:** [Рабочий проект стандарта C++: temp.spec.partial](https://eel.is/c++draft/temp.spec.partial)

239. Что такое операция `fold` над typelist?

	**Пример:**


## Очень сложный уровень

251. Что такое forwarding reference в шаблонах?

	**Ответ:** Forwarding reference — ссылка вида `T&&`, где `T` является выводимым cv-неквалифицированным параметром типа соответствующего шаблона функции. Она принимает lvalue и rvalue, сохраняя категорию в выведенном `T`.

	**Пример:**

	```cpp
	template<class T> void f(T&&) {}
	int x = 0;
	f(x); // T = int&
	f(1); // T = int
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.call](https://eel.is/c++draft/temp.deduct.call)

252. Чем `T&&` в шаблоне отличается от обычной rvalue-ссылки?

	**Ответ:** Для forwarding reference тип выводится по особому правилу для lvalue. `int&&`, `const T&&` и `T&&` с уже фиксированным параметром класса не являются forwarding references.

	**Пример:**

	```cpp
	template<class T> struct Box {
	    void fixed(T&&) {} // T уже задан специализацией класса
	    template<class U> void forwarding(U&&) {}
	};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.deduct.call](https://eel.is/c++draft/temp.deduct.call)

253. Что такое reference collapsing?

	**Ответ:** Это правила образования результирующей ссылки, когда через подстановку или alias возникает «ссылка на ссылку». Написать прямой тип `int& &` нельзя, но через псевдоним схлопывание допустимо.

	**Пример:**

	```cpp
	using L = int&;
	using R = L&&;
	static_assert(std::is_same_v<R, int&>);
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.ref](https://eel.is/c++draft/dcl.ref)

254. Какие правила схлопывания ссылок существуют?

	**Ответ:** Если хотя бы одна из двух ссылок является lvalue-ссылкой, результат — `&`. Только сочетание `&&` и `&&` даёт `&&`.

	**Пример:**

	```cpp
	using L = int&; using R = int&&;
	static_assert(std::is_same_v<L&, int&> && std::is_same_v<L&&, int&>);
	static_assert(std::is_same_v<R&, int&> && std::is_same_v<R&&, int&&>);
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.ref](https://eel.is/c++draft/dcl.ref)

255. Что такое perfect forwarding?

	**Ответ:** Perfect forwarding передаёт аргумент дальше с сохранением его cv-квалификаторов и категории значения. Обычно для этого сочетают forwarding reference и `std::forward<T>`.

	**Пример:**

	```cpp
	template<class F, class T> decltype(auto) call(F&& f, T&& x) {
	    return std::invoke(std::forward<F>(f), std::forward<T>(x));
	}
	```

	**Источник:** [Рабочий проект стандарта C++: forward](https://eel.is/c++draft/forward)

256. Зачем нужен perfect forwarding?

	**Ответ:** Он нужен обёрткам и фабрикам, чтобы lvalue оставались lvalue, а rvalue могли перемещаться. Именованный параметр сам по себе является lvalue-выражением даже при типе `T&&`.

	**Пример:**

	```cpp
	template<class T, class... Args> auto make(Args&&... args) {
	    return std::make_unique<T>(std::forward<Args>(args)...);
	}
	```

	**Источник:** [Рабочий проект стандарта C++: forward](https://eel.is/c++draft/forward)

257. Что делает `std::forward`?

	**Ответ:** `std::forward<T>(x)` выполняет приведение, сохраняющее исходную категорию при корректно выведенном `T`: lvalue остаётся lvalue, rvalue становится xvalue. Само по себе оно ничего не перемещает.

	**Пример:**

	```cpp
	int x = 1;
	static_assert(std::is_same_v<decltype(std::forward<int&>(x)), int&>);
	static_assert(std::is_same_v<decltype(std::forward<int>(x)), int&&>);
	```

	**Источник:** [Рабочий проект стандарта C++: forward](https://eel.is/c++draft/forward)

258. Чем `std::forward` отличается от `std::move`?

	**Ответ:** `std::move` безусловно превращает подходящее выражение в xvalue, сохраняя cv-квалификаторы; `std::forward<T>` делает это условно по `T`. Ни одна функция сама не вызывает перемещающий конструктор.

	**Пример:**

	```cpp
	template<class T> void pass(T&& x) {
	    auto&& preserved = std::forward<T>(x);
	    auto&& movable = std::move(x);
	}
	```

	**Источник:** [Рабочий проект стандарта C++: forward](https://eel.is/c++draft/forward)

259. Почему неправильное использование `std::move` в шаблонном коде опасно?

	**Ответ:** Безусловный `std::move` может разрешить перемещение из lvalue, принадлежащего вызывающему коду, хотя тот этого не ожидал. Для прозрачной передачи используют `std::forward` с выведенным типом.

	**Пример:**

	```cpp
	template<class T> std::string copy_or_move(T&& x) {
	    return std::string(std::forward<T>(x));
	}
	std::string s = "text";
	auto copy = copy_or_move(s); // s не перемещён
	```

	**Источник:** [Рабочий проект стандарта C++: forward](https://eel.is/c++draft/forward)

260. Что такое универсальный интерфейс фабричной функции через forwarding?

	**Ответ:** Это фабрика с пакетом forwarding references, передающая аргументы выбранному конструктору с сохранением категорий значений.

	**Пример:**

	```cpp
	template<class T, class... Args>
	std::unique_ptr<T> make(Args&&... args) {
	    return std::make_unique<T>(std::forward<Args>(args)...);

	```

261. Почему шаблоны часто используются для обёрток и адаптеров функций?

	**Ответ:** Шаблоны выводят тип callable и аргументов, позволяют проверить вызов, сохранить возвращаемые ссылки и передать значения без лишних копий.

	**Пример:**

262. Что такое callable constraints в generic-коде?

	**Ответ:** Это требования к возможности вызова, его аргументам, результату или отсутствию исключений. Категории значений в ограничении должны соответствовать реальному вызову.

	**Пример:**

	```cpp
	template<class F> requires std::invocable<F&, int>
	```

263. Что делает `std::invoke`?

	**Ответ:** `std::invoke` C++17 единообразно вызывает функции и функциональные объекты, а также обращается к членам через указатели на методы или поля.

	**Пример:**

	```cpp
	struct X { int value = 7; int get() const { return value; } };
	X x;
	int n = std::invoke(&X::get, x);
	int& ref = std::invoke(&X::value, x);
	```

264. Для чего нужен `std::invoke_result`?

	**Ответ:** `std::invoke_result<F, Args...>::type` описывает тип результата допустимого вызова по правилам `INVOKE`. Если вызов недопустим, члена `type` нет; доступно с C++17.

	**Пример:**

	```cpp
	using F = decltype([](int) { return 1.5; });
	using R = std::invoke_result_t<F, int>;
	static_assert(std::is_same_v<R, double>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.trans.other](https://eel.is/c++draft/meta.trans.other)

265. Что такое `std::is_invocable`?

	**Ответ:** `std::is_invocable<F, Args...>` проверяет допустимость вызова с заданными типами без его выполнения. Для многих таких traits действуют требования к полноте исследуемых типов.

	**Пример:**

	```cpp
	using F = int (*)(int);
	static_assert(std::is_invocable_v<F, int>);
	static_assert(!std::is_invocable_v<F, std::string>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.rel](https://eel.is/c++draft/meta.rel)

266. Как шаблонно проверить, можно ли вызвать объект с заданными аргументами?

	**Ответ:** Используют `std::is_invocable_v` C++17 или `std::invocable` C++20. Ссылочные квалификаторы типа callable важны: `F&` и `F&&` могут иметь разные операторы вызова.

	**Пример:**

	```cpp
	struct F { void operator()(int) & {} };
	static_assert(std::is_invocable_v<F&, int>);
	static_assert(!std::is_invocable_v<F, int>);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.rel](https://eel.is/c++draft/meta.rel)

267. Что такое CRTP?

	**Ответ:** CRTP — приём, при котором производный класс передаёт собственный тип в шаблон базового. База может вызывать интерфейс производного через статическое приведение.

	**Пример:**

	```cpp
	template<class D> struct Base { void run() { static_cast<D&>(*this).impl(); } };
	struct Job : Base<Job> { void impl() {} };
	Job job; job.run();
	```

	**Источник:** [LLVM: InstVisitor, пример статического полиморфизма](https://llvm.org/doxygen/InstVisitor_8h_source.html)

268. Как расшифровывается CRTP?

	**Ответ:** CRTP расшифровывается как Curiously Recurring Template Pattern — «странно повторяющийся шаблон». Повторяется имя производного типа в его же списке базовых классов.

	**Пример:**

	```cpp
	template<class D> struct Base {};
	struct Derived : Base<Derived> {};
	```

	**Источник:** [LLVM: InstVisitor, пример статического полиморфизма](https://llvm.org/doxygen/InstVisitor_8h_source.html)

269. Почему CRTP относят к статическому полиморфизму?

	**Ответ:** Конкретный производный тип является аргументом шаблона, поэтому целевая операция определяется при компиляции, без обязательного виртуального вызова.

	**Пример:**

	```cpp
	template<class D> struct Base { int value() const { return static_cast<const D&>(*this).impl(); } };
	struct X : Base<X> { int impl() const { return 7; } };
	```

	**Источник:** [Рабочий проект стандарта C++: expr.static.cast](https://eel.is/c++draft/expr.static.cast)

270. Чем CRTP отличается от виртуального полиморфизма?

	**Ответ:** CRTP создаёт разные базовые специализации для разных производных типов и связывает поведение статически. Виртуальный интерфейс позволяет работать с разными реализациями через один базовый тип во время выполнения.

	**Пример:**

	```cpp
	template<class D> struct Base {};
	struct A : Base<A> {}; struct B : Base<B> {};
	static_assert(!std::is_same_v<Base<A>, Base<B>>);
	```

	**Источник:** [Рабочий проект стандарта C++: class.virtual](https://eel.is/c++draft/class.virtual)

271. В каких случаях CRTP удобнее виртуальных функций?

	**Ответ:** Для статически известных типов, повторного использования поведения и возможностей инлайнинга, когда общий runtime-интерфейс не нужен. Выигрыш производительности необходимо измерять.

	**Пример:**

	```cpp
	template<class D> struct Twice { void run() { auto& d = static_cast<D&>(*this); d.step(); d.step(); } };
	```

272. Какие ограничения есть у CRTP?

	**Ответ:** Он связывает базу с конкретным производным типом, усложняет работу с неполным типом и не даёт общего полиморфного контейнера автоматически. Приведение к `D` корректно лишь когда база действительно является частью подходящего объекта.

	**Пример:**

	```cpp
	template<class D> struct Base { void run() { static_cast<D&>(*this).impl(); } };
	struct Job : Base<Job> { void impl() {} };
	// Не следует создавать отдельный Base<Job> и вызывать у него run().
	```

273. Что такое policy-based design?

	**Ответ:** Это проектирование, при котором отдельные стратегии поведения задаются типами-политиками. Основной шаблон объединяет их в конкретную реализацию.

	**Пример:**


274. Как шаблоны помогают строить policy-based архитектуру?

	**Ответ:** Политики становятся аргументами шаблона, поэтому выбор поведения и его проверка происходят при компиляции. Это удобно для статической конфигурации, но каждая комбинация создаёт отдельный тип.

283. Почему строки как параметры шаблона долгое время были неудобны?

285. Как `constexpr` и шаблоны дополняют друг друга?

286. Когда метапрограммирование через `constexpr` лучше классического TMP?

288. Что такое partial ordering шаблонов функций?

289. Как компилятор выбирает “более специализированный” шаблон?

291. Что такое friend injection и почему это нишевая тема в шаблонах?

	**Ответ:** Так называют приёмы объявления или определения namespace-функций через `friend` внутри шаблонов классов. Они взаимодействуют с ADL и инстанцированием; построение на них скрытого состояния компиляции особенно сложно и непереносимо в деталях.

	**Пример:**

	```cpp
	template<class T> struct Tag {
	    friend int value(Tag) { return 1; }

	```

292. Что такое ADL в контексте шаблонных функций?

	**Ответ:** Argument-dependent lookup добавляет к поиску неквалифицированного вызова функции из пространств имён и классов, связанных с типами аргументов. Это важный механизм расширения generic-кода.

	**Пример:**

	```cpp
	namespace app { struct X {}; void inspect(X) {} }
	template<class T> void call(T x) { inspect(x); }
	call(app::X{});
	```

	**Источник:** [Рабочий проект стандарта C++: basic.lookup.argdep](https://eel.is/c++draft/basic.lookup.argdep)

293. Почему ADL может неожиданно влиять на generic-код?

	**Ответ:** Тип аргумента может добавить к набору кандидатов функции, не видимые обычным поиском, и изменить выбор или создать неоднозначность. Квалифицированный вызов подавляет ADL.

	**Пример:**

	```cpp
	namespace app { struct X {}; void inspect(X) {} }
	app::X x;
	inspect(x);      // ADL
	app::inspect(x); // квалифицированный поиск
	```

	**Источник:** [Рабочий проект стандарта C++: basic.lookup.argdep](https://eel.is/c++draft/basic.lookup.argdep)

294. Что такое customization point object?

	```cpp
	std::vector<int> v{1, 2};
	```

295. Почему современная стандартная библиотека использует CPO-подход?

	**Ответ:** CPO позволяют объединить ограничения, правила выбора реализации и пользовательскую настройку за единым интерфейсом. Например, ranges-доступ выбирает между поддерживаемыми способами получить начало диапазона.

296. Чем CPO лучше прямого вызова функции в generic API?

297. Что такое hidden friends в шаблонном дизайне?

	```cpp
	template<class T> struct Box {
	```

298. Почему hidden friends полезны для операторов и ADL?

	**Пример:**

	```cpp
	struct X { int n; friend bool operator==(X a, X b) { return a.n == b.n; } };
	```

299. Что такое ranges и как они связаны с concepts и шаблонами?

300. Почему современное шаблонное программирование в C++ тесно связано с concepts, ranges и compile-time вычислениями?

## Экспертный уровень / метапрограммирование и дизайн

301. Что такое type-level programming?

	**Ответ:** Type-level programming — вычисления, входы и результаты которых представлены типами. Шаблоны преобразуют эти типы, выбирают варианты и строят новые структуры.

	**Пример:**

	```cpp
	template<class T> using Pointer = T*;
	using R = Pointer<int>; // результат вычисления — int*
	```

	**Источник:** [Рабочий проект стандарта C++: temp.alias](https://eel.is/c++draft/temp.alias)

302. Чем type-level programming отличается от value-level programming?

	**Ответ:** Type-level код преобразует типы, value-level код — значения. В C++ уровни взаимодействуют: `sizeof(T)` превращает информацию о типе в значение, а нетиповой аргумент делает значение частью типа.

	**Пример:**

	```cpp
	using T = std::remove_reference_t<int&>;
	constexpr auto n = sizeof(T);
	using Bytes = std::array<std::byte, n>;
	```

	**Источник:** [Рабочий проект стандарта C++: temp.arg.nontype](https://eel.is/c++draft/temp.arg.nontype)

303. Почему в TMP типы часто используются как носители информации?

	**Ответ:** Типы участвуют в перегрузке и специализации и могут хранить произвольную статическую структуру. Объекты таких типов для вычисления часто не нужны.

	**Пример:**

	```cpp
	using Yes = std::true_type;
	using Count = std::integral_constant<int, 3>;
	static_assert(Yes::value && Count::value == 3);
	```

	**Источник:** [Рабочий проект стандарта C++: meta.help](https://eel.is/c++draft/meta.help)

304. Что такое вычисление результата через вложенный `::type`?

	**Ответ:** Это соглашение, при котором специализация метафункции предоставляет результат как вложенный псевдоним. В зависимом контексте часто требуется `typename`.

	**Пример:**

	```cpp
	template<class T> struct Pointer { using type = T*; };
	template<class T> using Result = typename Pointer<T>::type;
	```

	**Источник:** [Рабочий проект стандарта C++: meta.rqmts](https://eel.is/c++draft/meta.rqmts)

305. Почему старый стиль TMP часто выглядел как “программирование на типах”?

	**Ответ:** До удобных constexpr-вычислений классы и специализации служили функциями и ветвлениями, а вложенные типы и константы — результатами. Даже значения часто оборачивали в типы.

	**Пример:**

	```cpp
	template<bool B> struct Select { typedef int type; };
	template<> struct Select<false> { typedef double type; };
	Select<false>::type x = 1.5;
	```

306. Что такое lazy instantiation в шаблонах?

	**Ответ:** Ленивое инстанцирование означает, что некоторые определения проверяются и порождаются только при необходимости. Например, создание объекта шаблонного класса обычно не требует тел всех его методов.

	**Пример:**

	```cpp
	template<class T> struct Box { void run() { T::run(); } };
	Box<int> b; // тело run() не требуется
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

307. Почему не весь шаблонный код инстанцируется сразу?

	**Ответ:** Правила инстанцирования отделяют получение структуры класса от необходимости определений его членов. Это позволяет использовать части шаблона с разными требованиями к параметрам.

	**Пример:**

	```cpp
	template<class T> struct Box {
	    T value;
	    void special() { value.special(); }
	};
	Box<int> b{1}; // special() не вызывается
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

308. Как ленивая инстанциация помогает generic-коду быть гибким?

	**Ответ:** Тип может поддерживать базовые операции, не поддерживая дополнительные возможности, пока последние не используются. Для более ясной диагностики дополнительные методы можно явно ограничивать.

	**Пример:**

	```cpp
	template<class T> struct Box {
	    T value;
	    void clear() requires requires(T& x) { x.clear(); } { value.clear(); }
	};
	Box<int> b{1};
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

309. Что такое dependent false idiom?

	**Ответ:** Это шаблонная булева константа, всегда равная `false`, но зависящая от параметра. Исторически она откладывала срабатывание `static_assert` до инстанцирования нужной ветви.

	**Пример:**

	```cpp
	template<class...> inline constexpr bool dependent_false = false;
	template<class T> void unsupported() { static_assert(dependent_false<T>, "Unsupported type"); }
	```

310. Для чего используют `dependent_false<T>`?

	**Ответ:** Для намеренной понятной ошибки в неподдерживаемом варианте шаблона, особенно при поддержке компиляторов без исправления CWG 2518/P2593R1.

	**Пример:**

	```cpp
	template<class> inline constexpr bool dependent_false = false;
	template<class T> void process(T) {
	    if constexpr (std::integral<T>) {}
	    else static_assert(dependent_false<T>, "Expected an integral type");
	}
	```

311. Почему `static_assert(false)` внутри шаблона не всегда подходит?

	**Ответ:** Раньше безусловный `static_assert(false)` в определении шаблона приводил к преждевременной ошибке. После CWG 2518/P2593R1 он не срабатывает в контексте определения шаблона до соответствующего инстанцирования; старые компиляторы могут требовать dependent false.

	**Пример:**

	```cpp
	template<class T> void unsupported() {
	    static_assert(false, "Unsupported type"); // требуется поддержка исправления
	}
	// unsupported<int>(); // ошибка при инстанцировании
	```

312. Как написать понятные `static_assert` для шаблонного кода?

	**Ответ:** Проверять конкретный инвариант как можно ближе к интерфейсу и писать сообщение о требуемом свойстве. Для ограничения набора перегрузок лучше подходит requires, а не ошибка в теле.

	**Пример:**

	```cpp
	template<class T> struct Buffer {
	    static_assert(std::is_trivially_copyable_v<T>, "Buffer requires a trivially copyable element");
	};
	```

	**Источник:** [Рабочий проект стандарта C++: dcl.pre](https://eel.is/c++draft/dcl.pre)

313. Почему хорошие сообщения об ошибках особенно важны в метапрограммировании?

	**Ответ:** Одна ошибка может породить длинную цепочку инстанцирований. Именованный concept или локальный `static_assert` помогает связать диагностику с нарушенным контрактом.

	**Пример:**

	```cpp
	template<class T> concept HasRun = requires(T& x) { x.run(); };
	template<HasRun T> void execute(T& x) { x.run(); }
	```

314. Что такое compile-time validation интерфейса типа?

	**Ответ:** Это проверка наличия и допустимости операций типа до выполнения программы. Синтаксические проверки не доказывают законы вроде транзитивности сравнения.

	**Пример:**

	```cpp
	template<class T> concept Runner = requires(T& x) { { x.run() } -> std::same_as<void>; };
	struct Job { void run() {} };
	static_assert(Runner<Job>);
	```

315. Как templates и concepts помогают переносить ошибки с runtime на compile time?

	**Ответ:** Они отклоняют несовместимые типы до построения программы: например, вызов сортировки с неподходящей категорией итератора. Ошибки внешних данных и динамического состояния всё равно требуют runtime-проверок.

	**Пример:**

	```cpp
	std::vector<int> v{3, 1, 2};
	std::ranges::sort(v); // ограничения проверяют пригодность диапазона
	```

316. Когда это действительно полезно, а когда только усложняет код?

	**Ответ:** Это полезно, когда свойство известно из типов или констант и предотвращает реальные ошибки использования. Пытаться кодировать динамические данные в типах обычно не стоит: это усложняет интерфейс без устранения runtime-проверок.

	**Пример:**

	```cpp
	template<std::size_t N> struct Buffer { static_assert(N > 0, "Buffer cannot be empty"); };
	Buffer<4> b;
	```

317. Что такое `constexpr`-контейнеры и compile-time объекты?

	**Ответ:** Это контейнеры и объекты, допустимые в константных вычислениях. `std::array` подходит для постоянного хранения; C++20 разрешает многие операции `vector` и `string` при вычислении, но динамическую память обычно нужно освободить до его завершения.

	**Пример:**

	```cpp
	constexpr int sum() { std::vector<int> v{1, 2, 3}; return v[0] + v[1] + v[2]; }
	static_assert(sum() == 6); // C++20, память v освобождается внутри вычисления
	```

318. Какие ограничения мешают полному “выполнению программы” на этапе компиляции?

	**Ответ:** Запрещены многие операции с внешним состоянием, обычный ввод-вывод и недопустимые обращения к памяти; действуют правила времени жизни и ограничения ресурсов компилятора. Наличие `constexpr` не разрешает произвольное выполнение.

	**Пример:**

	```cpp
	constexpr int divide(int a, int b) { return a / b; }
	// constexpr int bad = divide(1, 0); // не константное выражение
	```

319. Что такое reflection и почему в C++ тема рефлексии долго оставалась ограниченной?

	**Ответ:** Рефлексия предоставляет программе метаданные о собственных типах и объявлениях. В C++20/23 общей стандартной рефлексии нет: traits и requires дают лишь отдельные проверки. В рабочем проекте C++26 уже описана статическая рефлексия; её поддержку нужно проверять у конкретного компилятора.

	**Пример:**

	```cpp
	struct User { int id; };
	static_assert(std::is_class_v<User>); // доступно без рефлексии
	// Эта проверка не перечисляет имена полей User.
	```

	**Источник:** [Рабочий проект стандарта C++: meta.reflection](https://eel.is/c++draft/meta.reflection)

320. Какие возможности интроспекции типов уже есть без полной рефлексии?

	**Ответ:** Без общей рефлексии доступны traits, `decltype`, `sizeof`, requires-expressions, проверка операций и распознавание структур типов специализациями. Произвольный список имён всех полей получить такими средствами нельзя.

	**Пример:**

	```cpp
	template<class T> concept HasId = requires(T& x) { x.id; };
	struct User { int id; };
	static_assert(HasId<User>);
	```

321. Что такое `typeid` и почему это не метапрограммирование в полном смысле?

	**Ответ:** `typeid` даёт объект `std::type_info` со сведениями о типе; для полиморфного lvalue он может учитывать динамический тип объекта. Он не предоставляет общего механизма построения новых типов или перечисления полей.

	**Пример:**

	```cpp
	int x = 0;
	bool same = typeid(x) == typeid(int);
	```

322. Чем RTTI отличается от compile-time introspection?

	**Ответ:** RTTI позволяет исследовать типы во время выполнения, включая динамический тип полиморфного объекта. Compile-time introspection проверяет известные статические типы до выполнения и может влиять на выбор специализации.

	**Пример:**

	```cpp
	struct Base { virtual ~Base() = default; };
	struct Derived : Base {};
	Derived d; Base& b = d;
	bool dynamic = typeid(b) == typeid(Derived);
	static_assert(std::is_same_v<decltype(b), Base&>);
	```

323. Почему TMP часто использует нулевые объекты и пустые типы?

	**Ответ:** Пустые типы удобны как теги и политики: информация содержится в их типе, а не в состоянии объекта. «Нулевой объект» здесь не означает нулевой размер: размер отдельного объекта пустого класса ненулевой.

	**Пример:**

	```cpp
	struct Tag {};
	static_assert(std::is_empty_v<Tag>);
	static_assert(sizeof(Tag) >= 1);
	```

324. Что такое empty base optimization?

	**Ответ:** Empty base optimization позволяет пустому базовому подобъекту не занимать отдельное место, с учётом правил идентичности адресов. Это не означает нулевой размер самостоятельного объекта пустого класса.

	**Пример:**

	```cpp
	struct Empty {};
	struct Value : Empty { int n; };
	// На обычных ABI sizeof(Value) часто равно sizeof(int).
	```

329. Почему алгоритмы STL шаблонные?

332. Что такое категория итератора и как раньше она влияла на tag dispatch?

334. Что такое шаблонный API “на будущее расширение”?

335. Как не превратить шаблонный код в нечитаемую систему?

337. Какие признаки говорят, что metaprogramming здесь избыточно?

	**Ответ:** Признаки: единственная используемая специализация, сложные traits вокруг простой логики и затраты сборки без измеримой пользы. Решение оценивают по требованиям задачи, а не по количеству шаблонов.

338. Почему compile-time вычисления не всегда лучше runtime-вычислений?

	**Ответ:** Они увеличивают работу компилятора, ограничивают доступные данные и могут раздувать статические таблицы. Runtime-вычисление уместно для изменяемых данных или редко используемых результатов.

	**Пример:**

	```cpp
	constexpr int square(int x) { return x * x; }
	```

	**Источник:** [Рабочий проект стандарта C++: expr.const](https://eel.is/c++draft/expr.const)

339. Какие компромиссы между скоростью выполнения и скоростью компиляции возникают в TMP?

	**Ответ:** Специализация и предвычисление могут ускорить исполнение ценой времени сборки, памяти компилятора и размера программы. Обобщение через общий runtime-код может сократить сборку, но уменьшить возможности оптимизации.

	**Пример:**

	```cpp
	template<int Factor> int scale(int x) { return x * Factor; }
	int scale_runtime(int x, int factor) { return x * factor; }
	// Выбор между интерфейсами зависит от измерений и требований.
	```

	**Источник:** [Рабочий проект стандарта C++: temp.inst](https://eel.is/c++draft/temp.inst)

340. Какие основные принципы хорошего кода на шаблонах и метапрограммировании ты бы сформулировал?

	**Ответ:** Явно формулировать минимальные требования, сохранять понятную семантику и время жизни объектов, предпочитать простые реализации и измерять стоимость. Проверять обычные, граничные и неподдерживаемые типы; применять TMP там, где оно решает конкретную задачу.

	**Пример:**

	```cpp
	template<std::integral T> constexpr T twice(T x) { return x + x; }
	static_assert(twice(3) == 6);
	// Контракт также должен учитывать допустимый диапазон значений T.
	```

	**Источник:** [C++ Core Guidelines: T.10](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rt-concepts)
