## Filesystems & Storage — Questions (C/C++ oriented)

### Filesystems: ext4, xfs

1. Что такое файловая система?

   **Ответ:** Файловая система (FS) — это структура данных и набор программных механизмов ядра ОС, определяющие способ организации, хранения, адресации, именования и защиты файлов на носителе информации.

      **Пример:**

      ```bash
      df -Th

   ```

   **Типичная ошибка:** Путать файловую систему с физическим носителем: один накопитель может содержать несколько разных файловых систем.

   **Источник:** [man7: filesystems(5)](https://man7.org/linux/man-pages/man5/filesystems.5.html)

2. Зачем нужна файловая система поверх блочного устройства?

   **Ответ:** Блочное устройство предоставляет лишь плоский массив секторов фиксированного размера без структуры. Файловая система абстрагирует низкоуровневые секторы в человекочитаемые файлы, каталоги, метаданные (права доступа, временные метки), управляет свободным пространством и предотвращает фрагментацию.
   **Пример:**
   ```text
   [Приложение] -> open("log.txt") -> [VFS / Файловая система] -> LBA-сектора -> [Диск /dev/nvme0n1]

   ```

   **Типичная ошибка:** Считать, что ОС может адресовать файлы по имени напрямую на сыром дисковом разделе без промежуточной FS.
   **Источник:** [man7: filesystems(5)](https://man7.org/linux/man-pages/man5/filesystems.5.html)

3. Чем файловая система отличается от раздела диска?

   **Ответ:** Раздел диска (`partition`, например, `/dev/sda1`) — это физически или логически непрерывная область накопителя, заданная таблицей разделов (GPT/MBR). Файловая система — это внутренняя логическая структура данных, созданная внутри этого раздела при форматировании.
   **Пример:**
   ```bash
   lsblk -f
   # sda1 (раздел) -> ext4 (файловая система на разделе)

   ```

   **Типичная ошибка:** Думать, что создание раздела на диске (`fdisk`) автоматически делает его доступным для записи файлов (требуется создание FS через `mkfs`).
   **Источник:** [man7: fdisk(8)](https://man7.org/linux/man-pages/man8/fdisk.8.html)

4. Что такое ext4?

   **Ответ:** Четвертая версия расширенной файловой системы (Fourth Extended Filesystem) — журналируемая файловая система по умолчанию во многих дистрибутивах Linux. Поддерживает экстенты, отложенное выделение блоков, размеры томов до 1 ЭБ и файлов до 16 ТБ.
   **Пример:**
   ```bash
   mkfs.ext4 /dev/sdb1

   ```

   **Типичная ошибка:** Считать ext4 устаревшей: она стабильна, оптимизирована для универсальных нагрузок и активно поддерживается ядром.
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

5. Что такое XFS?

   **Ответ:** Высокопроизводительная 64-битная журналируемая файловая система, изначально разработанная компанией Silicon Graphics (SGI) для IRIX и портированная в Linux. Спроектирована для масштабируемости, параллельного ввода-вывода и работы с огромными файлами и накопителями (файловая система по умолчанию в RHEL/CentOS).
   **Пример:**
   ```bash
   mkfs.xfs /dev/nvme0n1p1

   ```

   **Типичная ошибка:** Полагать, что XFS медленнее ext4 на современных SSD: архитектура групп выделения (AG) дает отличную параллелизацию на многоядерных машинах.
   **Источник:** [man7: xfs(5)](https://man7.org/linux/man-pages/man5/xfs.5.html)

6. Чем ext4 концептуально отличается от XFS?

   **Ответ:** ext4 эволюционировала из блочной структуры ext2/ext3, используя фиксированные block groups с централизованными таблицами inode и возможностью журналирования как метаданных, так и данных. XFS изначально строилась на B+ деревьях, динамическом выделении inode и концепции Allocation Groups для параллельных независимых транзакций ввода-вывода.
   **Пример:**
   ```text
   ext4: традиционная иерархия блоков, таблица inode фиксируется при форматировании.
   XFS: B+ деревья для всего (экстенты, свободное место, inode), динамические inode.

   ```

   **Типичная ошибка:** Считать, что XFS позволяет уменьшать размер раздела файловой системы на лету (`shrink`). В отличие от ext4, уменьшение размера XFS не поддерживается в принципе.
   **Источник:** [man7: xfs(5)](https://man7.org/linux/man-pages/man5/xfs.5.html)

7. В каких сценариях часто выбирают ext4?

   **Ответ:** Для рабочих станций, серверов общего назначения, контейнеров с большим количеством мелких файлов, а также в системах, где требуется возможность уменьшения размера тома (`resize2fs shrink`) или поддержка полного журналирования данных (`data=journal`).
   **Пример:**
   ```bash
   # Изменение размера ext4 в обе стороны:
   resize2fs /dev/vg0/lv_data 50G

   ```

   **Типичная ошибка:** Выбирать ext4 для терабайтных баз данных без настройки `tune2fs`, оставляя стандартные 5% зарезервированного места под root (что теряет гигабайты на больших накопителях).
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

8. В каких сценариях часто выбирают XFS?

   **Ответ:** Для высоконагруженных СУБД (PostgreSQL, MySQL), хранилищ медиафайлов, аналитических платформ Big Data, а также серверов с многопоточными параллельными операциями записи на массивах NVMe/RAID.
   **Пример:**
   ```bash
   # XFS по умолчанию форматируется с поддержкой параллельных потоков аллокации
   mkfs.xfs -f -d agcount=16 /dev/nvme0n1

   ```

   **Типичная ошибка:** Использовать XFS в конфигурациях, требующих последующего уменьшения дискового раздела.
   **Источник:** [man7: xfs(5)](https://man7.org/linux/man-pages/man5/xfs.5.html)

9. Что такое journaling filesystem?

   **Ответ:** Файловая система, которая записывает информацию о предстоящих операциях модификации в специальную выделенную область диска (журнал) перед тем, как применить их к основным структурам файловой системы.
   **Пример:**
   ```bash
   # Просмотр параметров журнала ext4
   dumpe2fs -h /dev/sda1 | grep "Journal"

   ```

   **Типичная ошибка:** Считать, что журнал защищает от потери свежезаписанных данных приложений (он защищает в первую очередь целостность структуры самой файловой системы).
   **Источник:** [kernel.org: ext4 Journaling](https://www.google.com/search?q=https://docs.kernel.org/filesystems/ext4/journaling.html&utm_source=gemini)

10. Зачем нужен журнал в файловой системе?

   **Ответ:** Для предотвращения повреждения внутренней структуры FS (порчи каталогов, сиротских блоков, битых ссылок) при внезапном отключении питания или аппаратном сбое ОС, а также для исключения долгой процедуры полной проверки диска (`fsck`) при старте.
   **Пример:**
   ```text
   Сбой питания во время записи -> Перезагрузка -> Быстрое накатывание журнала (секунды) -> Диск смонтирован

   ```

   **Типичная ошибка:** Думать, что журнал делает вызовы `fsync()` ненужными для пользовательских приложений.
   **Источник:** [man7: fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)

11. Какие преимущества дает journaling?

   **Ответ:** Быстрое восстановление после сбоев (транзакции журнала накатываются или откатываются за доли секунды), консистентность метаданных, отсутствие необходимости полного сканирования всего диска при перезагрузке и непрерывная доступность сервисов.
   **Пример:**
   ```bash
   # Время монтирования диска на 10 ТБ после аварии: секунды вместо часов fsck
   mount /dev/sdb1 /mnt/data

   ```

   **Типичная ошибка:** Полагать, что journaling предотвращает появление нулевых байт внутри незавершенного файла при падении ОС (для этого требуется явная синхронизация через `fsync`).
   **Источник:** [kernel.org: ext4 Journaling](https://www.google.com/search?q=https://docs.kernel.org/filesystems/ext4/journaling.html&utm_source=gemini)

12. Какие накладные расходы может давать journaling?

   **Ответ:** Увеличение количества операций дисковой записи (двойная запись метаданных или данных), повышенная нагрузка на SSD (Write Amplification) и снижение пиковой пропускной способности при интенсивном случайном синхронном вводе-выводе.
   **Пример:**
   ```bash
   # Режим data=journal удваивает объем физической записи на диск
   mount -o data=journal /dev/sdb1 /mnt/logs

   ```

   **Типичная ошибка:** Включать режим `data=journal` на высоконагруженных базах данных, ожидая максимальной скорости работы.
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

13. Что происходит после сбоя питания в journaling FS?

   **Ответ:** При следующем монтировании драйвер файловой системы сканирует журнал: завершенные транзакции переносятся в основные структуры ФС (replay), а незавершенные — отбрасываются. Структуры возвращаются в гарантированно согласованное состояние без запуска полного `fsck`.
   **Пример:**
   ```text
   dmesg | grep "recovery complete"
   # [  2.100] EXT4-fs (sda1): recovery complete

   ```

   **Типичная ошибка:** Запускать принудительный ручной `fsck` на исправной журналируемой ФС после каждого аварийного отключения питания.
   **Источник:** [kernel.org: ext4 Journaling](https://www.google.com/search?q=https://docs.kernel.org/filesystems/ext4/journaling.html&utm_source=gemini)

14. Что такое metadata journaling?

   **Ответ:** Режим работы журнала, при котором в журнал записываются изменения только служебных структур ФС (размеры файлов, таблицы inode, указатели блоков, каталоги), а само тело пользовательских данных пишется сразу в основное пространство диска.
   **Пример:**
   ```bash
   # Стандартный режим ext4 (data=ordered) — журналирует метаданные,
   # гарантируя запись данных перед фиксацией метаданных в журнале
   mount -o data=ordered /dev/sda1 /mnt

   ```

   **Типичная ошибка:** Полагать, что metadata journaling гарантирует сохранность содержимого файла, который дописывался прямо в момент пропадания питания.
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

15. Что такое delayed allocation?

   **Ответ:** Механизм оптимизации записи (в ext4 опция `delalloc`), при котором ядро не выделяет физические блоки на диске в момент системного вызова `write()`, а откладывает аллокацию до момента физического сброса страниц из Page Cache на накопитель.
   **Пример:**
   ```text
   write() -> данные удерживаются в RAM -> ядро видит полный размер -> выделяет один непрерывный кусок блоков

   ```

   **Типичная ошибка:** Забывать вызывать `fsync()` при атомарной перезаписи файлов: при падении питания файл с `delalloc` может оказаться усеченным в 0 байт, если метаданные обновились, а данные не сбросились.
   **Источник:** [kernel.org: ext4 Delayed Allocation](https://docs.kernel.org/filesystems/ext4/dynamic.html)

16. Что такое extent?

   **Ответ:** Экстент — это непрерывная последовательность физических блоков диска, описываемая одной компактной записью вида: «начальный логический блок, начальный физический блок, длина последовательности блоков».
   **Пример:**
   ```text
   Вместо списка из 10 000 номеров блоков: [Экстент: блок 5000, длина 10 000]

   ```

   **Типичная ошибка:** Считать, что файл фрагментирован, если он занимает миллионы блоков, но адресован всего одним непрерывным экстентом.
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

17. Почему extent лучше списка блоков?

   **Ответ:** Экстенты резко сокращают объем метаданных, необходимых для адресации файла, снижают нагрузку на дисковые операции ввода-вывода метаданных и ускоряют последовательное чтение и запись больших файлов.
   **Пример:**
   ```bash
   # Просмотр карты экстентов файла
   filefrag -v large_file.bin

   ```

   **Типичная ошибка:** Полагать, что экстенты спасают от фрагментации при частой случайной дозаписи маленькими блоками в середину файла.
   **Источник:** [man7: filefrag(8)](https://man7.org/linux/man-pages/man8/filefrag.8.html)

18. Как ext4 хранит большие файлы?

   **Ответ:** С помощью B-дерева экстентов (`extent tree`), корень которого хранится прямо в дескрипторе `inode`. Если файл большой и одного узла мало, дерево разрастается до внутренних индексных узлов и листьев, вмещая файлы размером до 16 ТБ.
   **Пример:**
   ```bash
   debugfs -R "stat large_file" /dev/sda1

   ```

   **Типичная ошибка:** Думать, что ext4 до сих пор адресует большие файлы через тройные косвенные указатели (индексные блоки ext2/ext3).
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

19. Что такое fragmentation в файловой системе?

   **Ответ:** Состояние, при котором логически непрерывные данные одного файла или свободное пространство диска оказываются разбиты на множество мелких, физически разрозненных фрагментов по всему носителю.
   **Пример:**
   ```bash
   # Проверка степени фрагментации в ext4:
   e4defrag -c /path/to/my_file

   ```

   **Типичная ошибка:** Считать, что фрагментация на современных быстрых NVMe SSD снижает производительность так же критично, как на старых механических HDD (на SSD просадка заметна в основном на накладных расходах метаданных ядра).
   **Источник:** [man7: e4defrag(8)](https://man7.org/linux/man-pages/man8/e4defrag.8.html)

20. Почему fragmentation влияет на производительность?

   **Ответ:** На HDD фрагментация вызывает физические перемещения считывающих головок (seek latency). На SSD и NVMe сильная фрагментация раздувает деревья метаданных (разбивая экстенты на тысячи мелких кусков), увеличивая расход оперативной памяти ядра и снижая эффективность очередей I/O.
   **Пример:**
   ```text
   1 непрерывный экстент = 1 запрос ввода-вывода (IO request)
   5000 фрагментов = 5000 отдельных запросов к контроллеру диска

   ```

   **Типичная ошибка:** Игнорировать фрагментацию баз данных, активно растущих случайными маленькими вставками без предварительного выделения (`posix_fallocate`).
   **Источник:** [man7: posix_fallocate(3)](https://man7.org/linux/man-pages/man3/posix_fallocate.3.html)

21. Что такое directory indexing?

   **Ответ:** Механизм индексации содержимого директорий (в ext4 — `dir_index` на базе HTree), использующий хеш-деревья вместо линейного списка записей файлов.
   **Пример:**
   ```bash
   tune2fs -l /dev/sda1 | grep "dir_index"

   ```

   **Типичная ошибка:** Полагать, что файлы в директории на диске всегда хранятся в алфавитном порядке (при включенном `dir_index` они упорядочены по хешу имени).
   **Источник:** [man7: tune2fs(8)](https://man7.org/linux/man-pages/man8/tune2fs.8.html)

22. Как ускоряется поиск файлов в больших директориях?

   **Ответ:** Поиск файла выполняется по сбалансированному хеш-дереву (HTree в ext4 или B+ дереву в XFS) за $O(\log N)$ операций вместо линейного сканирования $O(N)$ всех записей каталога.
   **Пример:**
   ```bash
   # В каталоге с 1 000 000 файлов поиск по имени занимает микросекунды
   ls -U /mnt/huge_dir/target_file.txt

   ```

   **Типичная ошибка:** Использовать обычный `ls` без флага `-U` (без сортировки) на папках с сотнями тысяч файлов: задержка возникает на этапе сортировки имен в памяти утилитой `ls`, а не в ядре.
   **Источник:** [man7: ls(1)](https://man7.org/linux/man-pages/man1/ls.1.html)

23. Что такое superblock?

   **Ответ:** Ключевая структура данных файловой системы, расположенная по фиксированному смещению на диске и содержащая глобальные метаданные: геометрию ФС, размер блока, общее количество блоков и inode, статус монтирования и флаги возможностей.
   **Пример:**
   ```bash
   dumpe2fs /dev/sda1 | grep -i superblock

   ```

   **Типичная ошибка:** Считать, что суперблок существует в единственном экземпляре: ФС дублирует резервные копии суперблока (`backup superblocks`) по разным блочным группам для защиты от сбоев.
   **Источник:** [man7: mke2fs(8)](https://man7.org/linux/man-pages/man8/mke2fs.8.html)

24. Что хранится в superblock?

   **Ответ:** Размер блока ФС, количество свободных и занятых блоков и inode, UUID тома, метка диска (label), время последнего монтирования и записи, счетчик монтирований до проверки, размер журнала и поддерживаемые опции (extents, 64bit, dir_index).
   **Пример:**
   ```bash
   tune2fs -l /dev/sda1

   ```

   **Типичная ошибка:** Редактировать суперблок вручную через hex-редактор вместо использования утилит `tune2fs` или `xfs_admin`.
   **Источник:** [man7: tune2fs(8)](https://man7.org/linux/man-pages/man8/tune2fs.8.html)

25. Что такое block group в ext4?

   **Ответ:** Логическое деление раздела ext4 на независимые сегменты равного размера для локализации данных. Каждая группа блоков содержит копию суперблока (опционально), битовую карту блоков, битовую карту inode, таблицу inode и сами блоки данных.
   **Пример:**
   ```text
   [Block Group 0] [Block Group 1] ... [Block Group N]
   Каждая группа стремится хранить файлы каталога рядом с их дескрипторами inode.

   ```

   **Типичная ошибка:** Думать, что файл обязан целиком помещаться в одну группу блоков: если места не хватает, блоки берутся из соседних групп.
   **Источник:** [kernel.org: ext4 Block Groups](https://docs.kernel.org/filesystems/ext4/blockgroup.html)

26. Что такое allocation group в XFS?

   **Ответ:** Allocation Group (AG) — это независимый линейный регион файловой системы XFS, функционирующий практически как автономная мини-ФС со своими собственными B+ деревьями свободного места, inode и счетчиками.
   **Пример:**
   ```bash
   xfs_info /mnt/data | grep agcount

   ```

   **Типичная ошибка:** Считать AG простым аналогом блочной группы ext4: к каждой AG в XFS ядро обращается с собственными независимыми блокировками, что позволяет выполнять параллельные аллокации.
   **Источник:** [man7: xfs_info(8)](https://man7.org/linux/man-pages/man8/xfs_info.8.html)

27. Почему XFS хорошо работает на больших объемах данных?

   **Ответ:** Благодаря 64-битной архитектуре адресации, повсеместному использованию B+ деревьев масштабируемой глубины, эффективной работе с экстентами и отсутствию фиксированного ограничения на общее число inode при форматировании.
   **Пример:**
   ```text
   Поддерживает размеры файловых систем до 8 экзабайт и файлов до 8 экзабайт.

   ```

   **Типичная ошибка:** Ограничивать XFS фиксированным числом inode при форматировании: XFS динамически выделяет место под новые inode по мере создания файлов.
   **Источник:** [man7: xfs(5)](https://man7.org/linux/man-pages/man5/xfs.5.html)

28. Чем XFS удобен для параллельных I/O нагрузок?

   **Ответ:** Разделение дискового пространства на множество независимых групп выделения (Allocation Groups, AG). Потоки могут одновременно аллоцировать место и создавать файлы в разных AG без блокировки глобального мьютекса всей файловой системы.
   **Пример:**
   ```bash
   # Запуск 16 параллельных потоков записи распределяется по разным AG:
   mkfs.xfs -d agcount=16 /dev/sdb

   ```

   **Типичная ошибка:** Задавать слишком малое количество `agcount` на многоядерных серверах с быстрыми массивами дисков, создавая конкуренцию за замки одной AG.
   **Источник:** [man7: mkfs.xfs(8)](https://man7.org/linux/man-pages/man8/mkfs.xfs.8.html)

29. Поддерживает ли ext4 extents?

   **Ответ:** Да. Поддержка экстентов включена в ext4 по умолчанию и является одним из ключевых отличий ext4 от ее предшественницы ext3.
   **Пример:**
   ```bash
   tune2fs -l /dev/sda1 | grep "extent"
   # Filesystem features: ... extents ...

   ```

   **Типичная ошибка:** Попытка монтировать старые разделы ext3 драйвером ext4 с ожиданием мгновенного появления экстентов у существующих файлов: экстенты получают только вновь созданные файлы.
   **Источник:** [man7: ext4(5)](https://man7.org/linux/man-pages/man5/ext4.5.html)

30. Что такое fsck?

   **Ответ:** File System Consistency Check — системная утилита для проверки целостности и исправления логических ошибок, поврежденных структур метаданных и потерянных блоков в файловых системах.
   **Пример:**
   ```bash
   sudo fsck.ext4 -f /dev/sdb1

   ```

   **Типичная ошибка:** Запуск `fsck` на смонтированной в режиме чтения-записи (Read-Write) файловой системе, что гарантированно приводит к разрушению данных.
   **Источник:** [man7: fsck(8)](https://man7.org/linux/man-pages/man8/fsck.8.html)

31. Когда запускают fsck?

   **Ответ:** При обнаружении флага ошибки в суперблоке (dirty bit), при превышении счетчика монтирований или времени с прошлой проверки, либо вручную с LiveCD/Rescue-окружения для восстановления поврежденного диска.
   **Пример:**
   ```bash
   # Принудительная проверка при следующей перезагрузке ОС:
   sudo tune2fs -C 9999 /dev/sda1

   ```

   **Типичная ошибка:** Пытаться лечить аппаратные сбои диска (bad blocks) исключительно запуском `fsck`.
   **Источник:** [man7: fsck(8)](https://man7.org/linux/man-pages/man8/fsck.8.html)

32. Почему fsck может быть долгим на больших дисках?

   **Ответ:** В классических FS (ext4) утилите `fsck` требуется последовательно обойти все таблицы inode, сверить каждую битовую карту блоков и проверить дерево каталогов. На дисках объемом 10+ ТБ с миллионами файлов это может занять много часов.
   **Пример:**
   ```text
   fsck Pass 1: Checking inodes, blocks, and sizes... (миллионы случайных чтений метаданных)

   ```

   **Типичная ошибка:** Прерывать выполнение длительного `fsck` принудительной перезагрузкой сервера по питанию, повреждая частично исправленную структуру.
   **Источник:** [man7: e2fsck(8)](https://man7.org/linux/man-pages/man8/e2fsck.8.html)

33. Чем восстановление XFS отличается концептуально от ext4?

   **Ответ:** XFS полностью полагается на воспроизведение журнала (`journal replay`) при монтировании. Отдельная утилита `xfs_repair` запускается только при серьезных повреждениях, использует многопоточный параллельный алгоритм обхода по группам выделения (AG) и очищает поврежденные метаданные вместо попыток сложной реконструкции.
   **Пример:**
   ```bash
   sudo xfs_repair /dev/sdb1

   ```

   **Типичная ошибка:** Запуск `fsck.xfs /dev/sda1` с ожиданием глубокого сканирования: скрипт `fsck.xfs` в Linux ничего не делает, если журнал в порядке.
   **Источник:** [man7: xfs_repair(8)](https://man7.org/linux/man-pages/man8/xfs_repair.8.html)

34. Что такое mkfs.ext4?

   **Ответ:** Утилита создания (форматирования) файловой системы ext4 на блочном устройстве с инициализацией суперблоков, журнала и таблиц inode.
   **Пример:**
   ```bash
   sudo mkfs.ext4 -b 4096 -L "Storage" /dev/sdb1

   ```

   **Типичная ошибка:** Форматирование диска без указания метки (`-L label`), усложняющее последующее монтирование через `/etc/fstab`.
   **Источник:** [man7: mke2fs(8)](https://man7.org/linux/man-pages/man8/mke2fs.8.html)

35. Что такое mkfs.xfs?

   **Ответ:** Утилита инициализации файловой системы XFS на блочном разделе или файле-образе.
   **Пример:**
   ```bash
   sudo mkfs.xfs -f /dev/nvme0n1p2

   ```

   **Типичная ошибка:** Забывать флаг принудительной перезаписи `-f`, если на разделе уже содержались остатки старой файловой системы.
   **Источник:** [man7: mkfs.xfs(8)](https://man7.org/linux/man-pages/man8/mkfs.xfs.8.html)

36. Что произойдет при форматировании раздела?

   **Ответ:** Прежние корневые структуры метаданных и суперблоки перезаписываются новыми пустыми структурами ФС. Сами физические блоки данных на диске обычно не затираются нулями, но становятся недоступными через файловые дескрипторы ОС.
   **Пример:**
   ```bash
   mkfs.ext4 /dev/sdb1 # Метаданные перезаписаны, файлы отвязаны

   ```

   **Типичная ошибка:** Считать форматирование через `mkfs` безопасным стиранием конфиденциальных данных (файлы могут быть частично восстановлены с помощью инструментов восстановления вроде `photorec`).
   **Источник:** [man7: mkfs(8)](https://man7.org/linux/man-pages/man8/mkfs.8.html)

37. Как файловая система связана с page cache?

   **Ответ:** Файловая система работает с данными файлов через кэш страниц ядра (Page Cache). При вызовах `read()`/`write()` данные сначала считываются в страницы памяти ядра или модифицируются в них (становясь "грязными" — dirty pages), а затем периодически сбрасываются потоками ядра `flusher` на диск.
   **Пример:**
   ```text
   Пользователь -> write() -> Page Cache (память) -> flusher thread -> Файловая система -> Диск

   ```

   **Типичная ошибка:** Не учитывать, что весь объем свободной оперативной памяти в Linux автоматически утилизируется ядром под Page Cache.
   **Источник:** [man7: sync(2)](https://man7.org/linux/man-pages/man2/sync.2.html)

38. Что такое buffered I/O?

   **Ответ:** Стандартный механизм ввода-вывода в ОС, при котором операции чтения и записи обязательно проходят через системный кэш страниц ядра (`Page Cache`), ускоряя повторный доступ за счет сглаживания дисковых задержек.
   **Пример:**
   ```cpp
   #include <fcntl.h>
   #include <unistd.h>

   // Стандартный буферизованный I/O через ядро
   int fd = open("file.dat", O_RDWR | O_CREAT, 0644);
   write(fd, data, size);

   ```

   **Типичная ошибка:** Считать, что завершение вызова `write()` гарантирует физическое сохранение данных на блинах HDD или чипах SSD.
   **Источник:** [man7: write(2)](https://man7.org/linux/man-pages/man2/write.2.html)

39. Что такое direct I/O?

   **Ответ:** Режим прямого ввода-вывода (флаг `O_DIRECT` при вызове `open`), позволяющий передавать данные напрямую между пользовательским буфером процесса в памяти и контроллером накопителя в обход системного кэша страниц ядра (`Page Cache`).
   **Пример:**
   ```cpp
   #define _GNU_SOURCE
   #include <fcntl.h>

   // Прямой ввод-вывод для СУБД
   int fd = open("db.bin", O_RDWR | O_DIRECT);

   ```

   **Типичная ошибка:** Передавать в `read()`/`write()` буферы, не выровненные по размеру логического сектора диска (например, 512 или 4096 байт), что приводит к ошибке `EINVAL`.
   **Источник:** [man7: open(2)](https://man7.org/linux/man-pages/man2/open.2.html)

40. Когда приложению на C/C++ может быть важен выбор между ext4 и XFS?

   **Ответ:** 1) При проектировании серверов баз данных и хранилищ данных (высокая конкуренция за параллельное выделение блоков выгоднее на XFS). 2) При интенсивном создании сотен тысяч временных мелких файлов (ext4 быстрее освобождает мелкие метаданные). 3) При использовании прямого I/O (`O_DIRECT`), где XFS имеет более оптимизированный путь в ядре без глобальных блокировок `inode->i_rwsem`. 4) При использовании sparse-файлов и `fallocate()`.
   **Пример:**
   ```cpp
   #include <fcntl.h>

   // Предвыделение дискового пространства без записи нулей:
   // Поведение и задержки fallocate сильно оптимизированы под экстенты XFS
   int fd = open("store.img", O_RDWR | O_CREAT, 0644);
   posix_fallocate(fd, 0, 10ULL * 1024 * 1024 * 1024); // 10 GB

   ```

   **Типичная ошибка:** Тестировать производительность ввода-вывода C++ приложения только на локальной машине с ext4, сталкиваясь с неожиданной деградацией или, наоборот, приростом параллелизма при деплое в production под управлением XFS.
   **Источник:** [man7: posix_fallocate(3)](https://man7.org/linux/man-pages/man3/posix_fallocate.3.html)

### Inodes
41. Что такое inode?

   **Ответ:** Inode — объект файловой системы, описывающий файл: его тип, метаданные и расположение данных. Имя хранится отдельно в каталоге.

   **Пример:** `stat file`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

42. Что хранится в inode?

   **Ответ:** Тип, mode bits, UID/GID, размер, счётчик ссылок, временные метки и сведения о размещении данных. Конкретный формат зависит от ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

43. Хранится ли имя файла в inode?

   **Ответ:** Нет. Один inode может иметь несколько имён через hard links.

   **Пример:** `ln a b`.

   **Типичная ошибка:** Считать имя частью inode.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

44. Где хранится имя файла?

   **Ответ:** В записи каталога: она связывает имя с номером inode.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

45. Как каталог связывает имя файла и inode?

   **Ответ:** Каталог содержит записи «имя → inode»; поиск пути последовательно проходит такие записи.

   **Пример:** `ls -i dir`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

46. Чем inode отличается от file descriptor?

   **Ответ:** Inode описывает файл в ФС; FD — индекс в таблице дескрипторов процесса, ссылающийся на открытое файловое описание.

   **Пример:** Два `open()` одного файла дают независимые позиции чтения.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

47. Что такое inode number?

   **Ответ:** Номер inode уникален в пределах ФС, но может повторяться на другой ФС и переиспользоваться после удаления.

   **Пример:** Идентичность сравнивают по `st_dev` и `st_ino`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

48. Как посмотреть inode файла?

   **Ответ:** Командами `ls -i file` или `stat file`; из C — через `stat()`/`fstat()`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

49. Что означает link count inode?

   **Ответ:** Число жёстких ссылок на inode; открытые FD в него не входят.

   **Пример:** Поле `st_nlink`.

   **Типичная ошибка:** Приравнивать link count к числу открытий файла.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

50. Что такое hard link?

   **Ответ:** Дополнительная запись каталога, указывающая на существующий inode.

   **Пример:** `ln original alias`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

51. Как hard link связан с inode?

   **Ответ:** Hard link создаёт новое имя для того же inode, поэтому содержимое и права общие.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

52. Почему hard links указывают на один inode?

   **Ответ:** Потому что `link()` добавляет запись каталога с номером существующего inode, не создавая копию файла.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

53. Чем symlink отличается от hard link на уровне inode?

   **Ответ:** Symlink имеет собственный inode и хранит путь; hard link указывает непосредственно на inode исходного файла.

   **Пример:** Удаление исходного имени не ломает hard link.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

54. Может ли hard link ссылаться на директорию?

   **Ответ:** Обычным пользовательским `link()` — нет; Linux запрещает hard links на каталоги, включая вызовы с обычными root-привилегиями.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

55. Почему hard links на директории обычно запрещены?

   **Ответ:** Чтобы не создавать циклы в дереве каталогов и не нарушать обход, удаление и учёт родительских каталогов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

56. Что происходит с inode после удаления файла?

   **Ответ:** `unlink()` удаляет имя и уменьшает link count; inode остаётся, пока есть другие имена или активные ссылки на открытый файл.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

57. Когда inode реально освобождается?

   **Ответ:** Когда исчезли все hard links и последние активные ссылки ядра, включая открытые FD и отображения памяти.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

58. Что будет, если файл удален, но процесс все еще держит его открытым?

   **Ответ:** Имя исчезнет, но процесс сможет работать через FD; блоки освободятся после освобождения последних ссылок.

   **Пример:** `lsof +L1`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

59. Почему удаленный файл может продолжать занимать место на диске?

   **Ответ:** Открытое файловое описание или mapping продолжает удерживать объект, даже если link count равен нулю.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

60. Что такое metadata файла на уровне inode?

   **Ответ:** Тип, размер, владелец, группа, права, ссылки и временные метки; это описание файла, а не его пользовательское содержимое.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

61. Где хранятся права доступа файла?

   **Ответ:** Базовые mode bits связаны с inode; расширенные ACL обычно хранятся как дополнительные метаданные.

   **Пример:** `stat -c '%a' file`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

62. Где хранятся UID и GID файла?

   **Ответ:** В метаданных inode: `st_uid` и `st_gid` при чтении через `stat()`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

63. Где хранятся timestamps файла?

   **Ответ:** В метаданных inode; доступны через `stat()` и, с дополнительными возможностями, `statx()`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

64. Какие timestamps обычно есть у inode?

   **Ответ:** Обычно atime, mtime и ctime; birth time доступен через `statx()` при поддержке ФС.

   **Пример:** Считать `ctime` временем создания.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

65. Чем atime, mtime и ctime отличаются?

   **Ответ:** Atime — доступ к содержимому, mtime — изменение содержимого, ctime — изменение состояния inode. Обновление atime зависит от mount options.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

66. Что такое sparse file?

   **Ответ:** Файл с логическими областями нулей, для которых физические блоки могут не выделяться.

   **Пример:** `truncate -s 1G sparse.bin`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

67. Как inode описывает sparse file?

   **Ответ:** Метаданные размещения содержат только выделенные диапазоны; чтение дыр возвращает нули.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

68. Что такое inode exhaustion?

   **Ответ:** Исчерпание доступных inode или возможности выделить новые: создание файлов завершается `ENOSPC` даже при свободных блоках.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

69. Как может закончиться inode space при свободном месте на диске?

   **Ответ:** Свободные блоки данных и запас inode учитываются отдельно; особенно это заметно у ФС с фиксированными таблицами inode.

   **Пример:** `df -i`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

70. Почему большое количество мелких файлов может быть проблемой?

   **Ответ:** Нужны отдельные inode и записи каталогов; возрастает стоимость обхода, lookup, резервного копирования и метаданных.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

71. Как посмотреть число доступных inode в файловой системе?

   **Ответ:** Через `df -i /path`; смысл общего числа inode зависит от ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

72. Что происходит при переименовании файла с точки зрения inode?

   **Ответ:** Меняются записи каталогов и связанные метаданные; inode перемещаемого файла остаётся прежним в пределах ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

73. Меняется ли inode при rename()?

   **Ответ:** При успешном обычном `rename()` в пределах одного mount — нет.

   **Пример:** Считать, что новое имя означает новый файл.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

74. Что происходит с inode при copy файла?

   **Ответ:** При создании новой копии создаётся новый inode; reflink может разделять блоки данных, но inode всё равно отдельный.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

75. Что происходит с inode при move внутри одной ФС?

   **Ответ:** Обычно вызывается `rename()`: inode сохраняется, меняется имя или каталог.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

76. Что происходит с inode при move между разными ФС?

   **Ответ:** Обычный `mv` копирует данные в новый inode и затем удаляет исходник; единой атомарной операции нет.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

77. Как inode связан с stat()?

   **Ответ:** `stat()` возвращает метаданные объекта пути, включая `st_ino`; `fstat()` работает с уже открытым FD.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

78. Какие поля struct stat относятся к inode?

   **Ответ:** `st_ino`, `st_mode`, `st_nlink`, `st_uid`, `st_gid`, `st_size`, `st_blocks` и timestamps описывают файл; `st_dev` определяет ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

79. Почему понимание inode важно для системного C/C++ разработчика?

   **Ответ:** Помогает правильно понимать идентичность файлов, удаление открытых логов, hard links и гонки при работе с путями.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

80. Какие типичные баги связаны с inode и unlink/open?

   **Ответ:** Ожидание немедленного освобождения места после `unlink()`, чтение старого inode после замены файла и TOCTOU между проверкой пути и открытием.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man7/inode.7.html)

### mount / umount
81. Что такое mount в Linux?

   **Ответ:** Подключение файловой системы или её поддерева к точке в дереве путей текущего mount namespace.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

82. Что именно “монтируется” в Linux?

   **Ответ:** Обычно экземпляр ФС с блочного устройства, сетевого ресурса либо псевдо-ФС; bind mount подключает уже существующее поддерево.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

83. Что такое mount point?

   **Ответ:** Каталог, в котором становится доступен корень подключённой ФС; прежнее содержимое каталога временно скрывается.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

84. Почему без mount файловая система недоступна через дерево каталогов?

   **Ответ:** VFS разрешает пути через дерево mount points; несмонтированная дисковая ФС не включена в это дерево. Сырые блоки устройства всё ещё доступны отдельно.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

85. Что такое root filesystem?

   **Ответ:** Файловая система, видимая по `/` в данном окружении; при загрузке начальный root может заменяться основным.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

86. Как посмотреть список смонтированных ФС?

   **Ответ:** Через `findmnt`, `/proc/self/mountinfo` или `mount`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

87. Что делает команда mount без аргументов?

   **Ответ:** Выводит список подключённых файловых систем и их параметры; для скриптов удобнее `findmnt`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

88. Что делает /etc/fstab?

   **Ответ:** Описывает постоянные настройки монтирования и swap; используется утилитами и менеджером загрузки.

   **Пример:** `mount -a` обрабатывает подходящие записи.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

89. Что хранится в /etc/fstab?

   **Ответ:** Источник, точка монтирования, тип ФС, options, dump flag и порядок fsck.

   **Пример:** `UUID=... /data ext4 defaults 0 2`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

90. Чем ручной mount отличается от auto-mount через fstab?

   **Ответ:** Ручной mount меняет текущее состояние; fstab задаёт конфигурацию для загрузки или `mount -a`. Fstab сам по себе не означает монтирование по обращению.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

91. Что такое UUID раздела?

   **Ответ:** В fstab `UUID=` обычно означает UUID файловой системы; UUID записи GPT задаётся как `PARTUUID=`.

   **Пример:** `blkid`.

   **Типичная ошибка:** Смешивать UUID ФС и PARTUUID.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

92. Почему часто используют UUID вместо /dev/sdX?

   **Ответ:** Имена `/dev/sdX` зависят от обнаружения устройств; UUID обычно сохраняется при смене порядка подключения.

   **Пример:** Клонирование диска может создать дубликаты UUID.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

93. Что такое LABEL файловой системы?

   **Ответ:** Человекочитаемая метка ФС, используемая как `LABEL=`; уникальность нужно обеспечивать самостоятельно.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

94. Что такое loop mount?

   **Ответ:** Подключение обычного файла как блочного устройства через loop driver с последующим mount.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

95. Как примонтировать ISO образ?

   **Ответ:** Например, `sudo mount -o loop,ro image.iso /mnt/iso`; каталог должен существовать. Команда изменяет mounts системы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

96. Что такое bind mount?

   **Ответ:** Дополнительное подключение существующего каталога в другое место дерева.

   **Пример:** `mount --bind /srv/data /mnt/data`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

97. Когда используют bind mount?

   **Ответ:** Для представления данных в другом пути, chroot или контейнере без копирования содержимого.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

98. Что такое tmpfs?

   **Ответ:** Файловая система в виртуальной памяти: страницы используют RAM и могут вытесняться в swap согласно настройкам.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

99. Чем tmpfs отличается от дисковой ФС?

   **Ответ:** Данные не сохраняются после размонтирования/перезагрузки; потребление ограничено памятью, swap и лимитами tmpfs.

   **Пример:** Считать tmpfs всегда исключительно RAM.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

100. Что такое pseudo-filesystems вроде procfs и sysfs?

   **Ответ:** Интерфейсы ядра в виде файлов: procfs показывает процессы и параметры, sysfs — объекты устройств и подсистем.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

101. Можно ли монтировать procfs и sysfs?

   **Ответ:** Да: `mount -t proc proc /proc` и `mount -t sysfs sysfs /sys` при достаточных полномочиях и разрешениях namespace.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

102. Что такое read-only mount?

   **Ответ:** Mount, через который запрещены операции изменения файловой системы.

   **Пример:** `findmnt -o TARGET,OPTIONS`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

103. Когда полезен mount -o ro?

   **Ответ:** Для чтения образов, защиты от случайных изменений и восстановления. Для некоторых ФС replay журнала возможен даже при `ro`, нужны специальные recovery options.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

104. Что такое noexec, nosuid, nodev?

   **Ответ:** `noexec` запрещает прямой exec файлов, `nosuid` отключает SUID/SGID и file capabilities, `nodev` запрещает интерпретировать device nodes.

   **Пример:** Считать `noexec` полноценной песочницей.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

105. Зачем используют mount options для безопасности?

   **Ответ:** Они сокращают доступные способы исполнения кода и повышения привилегий; дополняют права и LSM.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

106. Что такое remount?

   **Ответ:** Изменение параметров уже подключённой ФС без обычного полного unmount/mount.

   **Пример:** `mount -o remount,ro /data`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

107. Когда нужен remount?

   **Ответ:** При переключении read-only/read-write или изменении поддерживаемых параметров. Не все options допускают изменение на лету.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

108. Что делает umount?

   **Ответ:** Отсоединяет mount от дерева путей; обычный успешный unmount завершает необходимые операции ФС и освобождает ресурсы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

109. Почему umount может завершиться ошибкой “target is busy”?

   **Ответ:** ФС удерживают открытые файлы, текущие каталоги процессов, mappings или вложенные mounts.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

110. Как понять, кто держит mount busy?

   **Ответ:** Через `fuser -vm /mountpoint`, `lsof` и `findmnt -R /mountpoint`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

111. Что такое lazy unmount?

   **Ответ:** `umount -l` сразу отсоединяет mount от дерева, но окончательное освобождение откладывается до исчезновения ссылок.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

112. Когда используют umount -l?

   **Ответ:** Для отсоединения занятого mount, например при проблемном сетевом ресурсе. Это не подтверждение записи всех данных и не разрешение извлекать диск.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

113. Что такое forced unmount?

   **Ответ:** `umount -f` просит поддерживающую это ФС принудительно размонтироваться; главным образом актуально для некоторых сетевых ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

114. Почему unmount сетевых ФС может быть отдельной проблемой?

   **Ответ:** RPC могут ожидать недоступный сервер, а грязные данные — подтверждения записи; поведение зависит от NFS/CIFS и mount options.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

115. Что происходит, если вытащить устройство без umount?

   **Ответ:** Неуспевшие попасть на носитель данные могут потеряться; возможны ошибки I/O и повреждение структуры ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

116. Почему unmount важен для целостности данных?

   **Ответ:** Он завершает отложенные операции и синхронизацию в рамках гарантий ФС и устройства; неисправный контроллер эти гарантии нарушает.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

117. Как mount/umount связан с VFS?

   **Ответ:** VFS связывает mounts с деревом путей и делегирует реализацию конкретной ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

118. Что такое namespace mount points в Linux?

   **Ответ:** Mount namespace имеет своё представление mount tree; распространение изменений зависит от shared/private/slave propagation.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

119. Как контейнеры используют mount namespaces?

   **Ответ:** Они формируют отдельное дерево mounts: rootfs образа, bind mounts, volumes и псевдо-ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

120. Почему понимание mount важно для backend/system developer?

   **Ответ:** Помогает объяснять различия путей хоста и контейнера, недоступные файлы, read-only ошибки и занятые mounts.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/mount.8.html)

### Disk Usage: df, du
121. Что показывает df?

   **Ответ:** Использование блоков и доступную ёмкость смонтированной ФС, а не сумму размеров файлов.

   **Пример:** `df -h /var`.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

122. Что показывает du?

   **Ответ:** Занятые блоки файлов и каталогов, найденных обходом дерева.

   **Пример:** `du -sh /var/log`.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

123. Чем df отличается от du?

   **Ответ:** `df` получает счётчики ФС; `du` обходит доступные имена и суммирует размещение найденных файлов.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

124. Почему df и du могут показывать разные значения?

   **Ответ:** Причины: открытые удалённые файлы, метаданные, reserved blocks, snapshots, скрытые mounts и недоступные каталоги.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

125. Что такое “used”, “available”, “capacity” в df?

   **Ответ:** Used — занятые блоки, available — доступные обычному пользователю, capacity/use% — доля использования с учётом правил утилиты и резервирования.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

126. Что показывает df -h?

   **Ответ:** Размеры в удобных единицах на основе степеней 1024; `-H` использует степени 1000.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

127. Что показывает du -sh?

   **Ответ:** `-s` даёт итог для аргумента, `-h` форматирует размер.

   **Пример:** `du -sh /srv/data`.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

128. Как посмотреть размер конкретной директории?

   **Ответ:** Командой `du -sh /path`; для логического размера добавляют `--apparent-size`.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

129. Как посмотреть размеры поддиректорий первого уровня?

   **Ответ:** GNU du: `du -h --max-depth=1 /path`; `-x` ограничит обход одной ФС.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

130. Почему du на большой директории может работать долго?

   **Ответ:** Нужно обойти записи каталогов и получить метаданные множества объектов; это дорого на холодном кеше и сетевых ФС.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

131. Считает ли du hard links несколько раз?

   **Ответ:** GNU du обычно считает один inode один раз в рамках запуска; `--count-links` меняет поведение.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

132. Как открытые, но удаленные файлы влияют на df?

   **Ответ:** Блоки продолжают числиться занятыми в `df`, хотя обычный `du` по именам их не обнаружит.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

133. Почему после удаления большого лог-файла место может не освободиться сразу?

   **Ответ:** Пишущий процесс удерживает FD старого inode; нужен корректный reopen после rotation либо закрытие дескриптора.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

134. Как найти крупные директории на диске?

   **Ответ:** `du -xhd1 /var` и затем уточнение наиболее крупных подкаталогов; ошибки доступа нельзя игнорировать.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

135. Как найти крупные файлы в Linux?

   **Ответ:** Например, `find /var -xdev -type f -size +1G -print`; логический размер не всегда равен занятым блокам.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

136. Что такое apparent size?

   **Ответ:** Логический размер файла — позиция конца файла, обычно `st_size`.

   **Пример:** `du --apparent-size -h file`.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

137. Чем apparent size отличается от реально занятых блоков?

   **Ответ:** Sparse files могут иметь большой логический размер при небольшом выделении блоков; preallocation и метаданные дают другие расхождения.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

138. Как sparse files влияют на du?

   **Ответ:** Обычный `du` считает выделенные блоки, а `du --apparent-size` — логический размер.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

139. Как inode exhaustion проявляется при df?

   **Ответ:** Обычный `df` может показывать свободные гигабайты; `df -i` при этом покажет исчерпание inode.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

140. Почему df -i иногда важнее обычного df?

   **Ответ:** Создание даже пустого файла требует inode: свободные блоки не помогают, когда inode закончились.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

141. Что показывает df -i?

   **Ответ:** Общее число, использованные и свободные inode и процент их использования; данные зависят от возможностей ФС.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

142. Как понять, что закончились inode, а не место?

   **Ответ:** Сопоставить `df -h` и `df -i` для той же точки; также проверить quotas и ограничения конкретной ФС.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

143. Почему логирование может быстро забить диск?

   **Ответ:** Поток сообщений, отсутствие retention, повторяющиеся ошибки и незакрытые удалённые логи дают неограниченный рост.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

144. Как rotation логов помогает управлять местом?

   **Ответ:** Rotation ограничивает размер и срок хранения, сжимает старые логи; процесс должен переключиться на новый файл.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

145. Что такое reserved blocks в ext4?

   **Ответ:** Часть блоков, зарезервированная для привилегированных записей и работы системы при заполнении ФС.

   **Пример:** `tune2fs -l /dev/DEVICE` для ext4.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

146. Почему root может видеть иное доступное место?

   **Ответ:** Привилегированный процесс может использовать резерв, недоступный обычному пользователю; `Avail` обычно показывает обычную доступность.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

147. Как посмотреть usage tmpfs?

   **Ответ:** Через `df -h /dev/shm` и `df -i /dev/shm`; точка tmpfs может быть другой.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

148. Почему tmpfs тоже может “закончиться”?

   **Ответ:** Есть лимиты размера и inode, а также ограничения RAM, swap и cgroup памяти.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

149. Как page cache влияет на восприятие дискового использования?

   **Ответ:** Page cache занимает RAM, не является дополнительной независимой копией на диске; dirty pages означают ещё не завершённую запись.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

150. Какие команды полезны при расследовании “куда пропало место”?

   **Ответ:** `df -h`, `df -i`, `du -xhd1`, `findmnt`, `lsof +L1`; дополнительно проверяют quotas и snapshots.

   **Источник:** [Документация](https://www.gnu.org/software/coreutils/manual/html_node/Disk-usage.html)

### Partitions
151. Что такое partition?

   **Ответ:** Диапазон секторов устройства, описанный записью в таблице разделов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

152. Зачем делить диск на разделы?

   **Ответ:** Для разделения загрузки, swap и данных, независимых ФС, лимитов и административных операций.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

153. Чем partition отличается от filesystem?

   **Ответ:** Раздел задаёт диапазон блоков; ФС задаёт организацию файлов внутри блочного устройства.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

154. Что такое MBR?

   **Ответ:** Историческая таблица разделов в начале диска; обычно четыре primary entries и ограничения 32-битной адресации LBA.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

155. Что такое GPT?

   **Ответ:** GUID Partition Table: записи с GUID, резервная копия таблицы и контрольные суммы, поддержка больших дисков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

156. Чем GPT лучше MBR?

   **Ответ:** GPT поддерживает больше разделов и большие адресные пространства, имеет резервирование метаданных; MBR совместим со старой загрузкой.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

157. Что такое partition table?

   **Ответ:** Метаданные, определяющие границы, типы и идентификаторы разделов.

   **Пример:** `fdisk -l`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

158. Что такое primary partition?

   **Ответ:** Раздел, непосредственно описанный одной из четырёх основных MBR-записей; для GPT это деление не применяется.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

159. Что такое logical partition?

   **Ответ:** Раздел внутри extended partition MBR, описанный цепочкой EBR.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

160. Почему GPT практически вытеснил MBR?

   **Ответ:** GPT снимает многие ограничения размера и числа разделов MBR и соответствует распространённой UEFI-загрузке.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

161. Как посмотреть список разделов в Linux?

   **Ответ:** `lsblk`, `fdisk -l`, `parted -l`; подробность и необходимые права различаются.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

162. Что показывает lsblk?

   **Ответ:** Дерево блочных устройств: диски, разделы, device-mapper, типы и точки mounts.

   **Пример:** `lsblk -f` добавляет сведения о ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

163. Что показывает blkid?

   **Ответ:** Сигнатуры устройств: тип ФС, UUID, LABEL и иногда PARTUUID.

   **Пример:** `blkid /dev/DEVICE`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

164. Что показывает fdisk -l?

   **Ответ:** Таблицы разделов, размеры, типы и границы доступных дисков; это просмотр, без режима записи.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

165. Что такое sector?

   **Ответ:** Адресуемая единица блочного устройства; logical и physical sector могут иметь разные размеры.

   **Пример:** Часто 512 или 4096 байт, но не следует хардкодить.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

166. Что такое block device?

   **Ответ:** Устройство с адресуемым доступом к блокам; представлено специальным файлом и драйвером ядра.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

167. Почему /dev/sda и /dev/sda1 — это разные сущности?

   **Ответ:** Первое обозначает весь диск, второе — диапазон раздела; запись в весь диск может затронуть таблицу разделов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

168. Как раздел связан с устройством /dev?

   **Ответ:** Ядро создаёт отдельное блочное устройство раздела; devtmpfs/udev обеспечивают его имя в `/dev`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

169. Что такое alignment разделов?

   **Ответ:** Выравнивание начала и границ раздела относительно физических секторов и оптимальных I/O-границ.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

170. Почему alignment важен для SSD и RAID?

   **Ответ:** Невыровненные записи могут пересекать физические блоки или RAID stripes, вызывая дополнительный read-modify-write.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

171. Можно ли создать файловую систему прямо на диске без partition table?

   **Ответ:** Да, ФС может занимать всё блочное устройство без таблицы разделов.

   **Пример:** Требования загрузки и инструментов нужно учитывать отдельно.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

172. Когда это может быть допустимо?

   **Ответ:** Для выделенного диска данных или виртуального устройства, когда отдельные разделы не нужны.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

173. Что такое swap partition?

   **Ответ:** Раздел, подготовленный для swap: хранения вытесненных анонимных страниц и, при настройке, образа гибернации.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

174. Чем swap partition отличается от swap file?

   **Ответ:** Раздел — отдельное устройство, файл — размещение внутри ФС. Swap file должен удовлетворять ограничениям ФС по дыркам и COW.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

175. Когда полезен отдельный раздел /boot?

   **Ответ:** Когда загрузчику нужен простой доступ к ядру/initramfs, например при сложном шифровании; `/boot` и EFI System Partition — разные роли.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

176. Когда полезен отдельный раздел /var?

   **Ответ:** Чтобы рост логов и очередей не исчерпал корневую ФС; заполнение `/var` всё равно требует обработки.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

177. Когда полезен отдельный раздел /home?

   **Ответ:** Для отделения пользовательских данных, переустановки системы и независимого управления ёмкостью.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

178. Почему раздельные partitions помогают администрированию?

   **Ответ:** Можно независимо монтировать, проверять, резервировать и ограничивать области данных.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

179. Какие риски у слишком мелкой нарезки диска на разделы?

   **Ответ:** Свободное место оказывается не там, где нужно; изменение границ сложнее, растут расходы на обслуживание.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

180. Как partitions влияют на производительность и управляемость?

   **Ответ:** Они дают управляемость, но сами по себе не создают отдельную пропускную способность одного физического диска.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/fdisk.8.html)

### LVM
181. Что такое LVM?

   **Ответ:** Logical Volume Manager — слой управления блочными томами через PV, VG и LV поверх device mapper.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

182. Какие проблемы решает LVM?

   **Ответ:** Позволяет гибко выделять место, расширять тома, переносить extents и делать snapshots.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

183. Чем LVM отличается от обычных partitions?

   **Ответ:** Обычные разделы привязаны к границам диска; LV собирается из extents пула и может охватывать устройства.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

184. Что такое PV (Physical Volume)?

   **Ответ:** Physical Volume — устройство, подготовленное для участия в LVM и содержащее метаданные/область extents.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

185. Что такое VG (Volume Group)?

   **Ответ:** Volume Group — пул пространства из одного или нескольких PV.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

186. Что такое LV (Logical Volume)?

   **Ответ:** Logical Volume — виртуальное блочное устройство, выделенное из VG; поверх него размещают ФС или другие данные.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

187. Как PV, VG и LV связаны между собой?

   **Ответ:** PV входят в VG, а VG предоставляет extents для LV.

   **Пример:** `pvs`, `vgs`, `lvs`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

188. Почему LVM удобно для гибкого управления хранилищем?

   **Ответ:** Размер и размещение LV можно менять независимо от жёсткой нарезки дисков; ограничения ФС остаются.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

189. Что такое extent в LVM?

   **Ответ:** Единица распределения пространства VG; extents LV отображаются на extents физических томов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

190. Как расширить logical volume?

   **Ответ:** Например, `lvextend -L +10G /dev/vg/data`, затем расширить ФС; свободное место должно быть в VG. Это пример изменения конфигурации.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

191. Можно ли уменьшать LVM volume?

   **Ответ:** Да, но сначала безопасно уменьшают поддерживающую shrink ФС, затем LV; XFS штатный shrink не поддерживает.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

192. Почему shrink volume опаснее, чем grow?

   **Ответ:** Уменьшение LV раньше ФС отрезает используемые блоки и повреждает данные; необходимы backup и проверка порядка действий.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

193. Как расширить ФС после увеличения LV?

   **Ответ:** Ext4 расширяют `resize2fs /dev/vg/data`, XFS — `xfs_growfs /mountpoint`; `lvextend -r` может совместить этапы при поддержке.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

194. Можно ли сделать snapshot в LVM?

   **Ответ:** Да: существуют классические COW snapshots и thin snapshots; требования к месту различаются.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

195. Что такое LVM snapshot?

   **Ответ:** Представление состояния блоков тома на момент создания с последующим сохранением отличий.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

196. Для чего используют snapshots?

   **Ответ:** Для согласованного исходного состояния backup и тестов; согласованность приложения требует flush/freeze или механизма самой БД.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

197. Какие ограничения у snapshots?

   **Ответ:** Snapshot не заменяет backup, расходует место при изменениях и может ухудшать I/O; переполнение зависит от типа snapshot/pool.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

198. Как LVM помогает при миграции данных между дисками?

   **Ответ:** `pvmove` переносит extents между PV, после чего устройство можно вывести из VG при соблюдении процедуры.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

199. Можно ли объединить несколько физических дисков в один VG?

   **Ответ:** Да. При линейном LV потеря одного PV может сделать недоступным весь LV; объединение не означает RAID.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

200. Как LVM взаимодействует с RAID?

   **Ответ:** Можно разместить PV на md RAID либо использовать LVM RAID LV. Отказоустойчивость зависит от выбранной схемы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

201. Как LVM отображается в /dev?

   **Ответ:** Обычно `/dev/VG/LV` и `/dev/mapper/...`; это имена device-mapper устройств.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

202. Что такое device mapper?

   **Ответ:** Подсистема ядра для отображения виртуальных блоков на нижележащие устройства; используется LVM, dm-crypt и другими слоями.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

203. Как посмотреть структуру LVM в системе?

   **Ответ:** `lsblk`, `pvs`, `vgs`, `lvs -a -o +devices`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

204. Какие команды используются для PV/VG/LV?

   **Ответ:** Просмотр: `pvs/vgs/lvs`; изменения: `pvcreate`, `vgcreate`, `lvcreate`, `lvextend`, `pvmove` и другие специализированные команды.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

205. Когда LVM особенно полезен на серверах?

   **Ответ:** При росте данных, добавлении дисков, миграциях и необходимости менять ёмкость томов без перестройки разделов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

206. Какие риски или минусы у LVM?

   **Ответ:** Дополнительный слой метаданных и сложности восстановления; thin pools и snapshots требуют отдельного мониторинга.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

207. Как LVM влияет на восстановление после сбоев?

   **Ответ:** Нужно восстановить и блочный слой LVM, и ФС; копии конфигурации VG не содержат пользовательские данные.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

208. Можно ли ставить файловую систему поверх LV?

   **Ответ:** Да, LV предоставляет обычное блочное устройство, пригодное для создания ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

209. Почему LVM часто используют вместе с ext4 или XFS?

   **Ответ:** Обе ФС работают поверх блочных устройств и поддерживают увеличение размера; LVM управляет ёмкостью ниже уровня ФС.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

210. Что важно знать о LVM C/C++ разработчику, а не только админу?

   **Ответ:** Приложение должно обрабатывать I/O-ошибки, ENOSPC и latency при snapshots/migrations, а не полагаться на физическую конфигурацию диска.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man8/lvm.8.html)

### RAID
211. Что такое RAID?

   **Ответ:** Организация нескольких устройств в массив с распределением данных, зеркалированием и/или избыточностью.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

212. Какие задачи решает RAID?

   **Ответ:** Повышает доступность и/или производительность; конкретные свойства определяются уровнем RAID.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

213. Чем RAID отличается от backup?

   **Ответ:** RAID сохраняет доступность при части аппаратных отказов; backup восстанавливает прежние данные после удаления, порчи или атаки.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

214. Что такое striping?

   **Ответ:** Разбиение данных на полосы и распределение их по дискам.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

215. Что такое mirroring?

   **Ответ:** Хранение одинаковых данных на нескольких устройствах.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

216. Что такое parity?

   **Ответ:** Вычисленная из данных избыточная информация для восстановления недостающих блоков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

217. Что такое RAID 0?

   **Ответ:** Чередование данных без избыточности; отказ любого диска обычно разрушает массив.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

218. Какие плюсы RAID 0?

   **Ответ:** Суммарная ёмкость и параллельный I/O при подходящей нагрузке.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

219. Какие минусы RAID 0?

   **Ответ:** Нет отказоустойчивости; вероятность потери массива растёт с числом зависимых устройств.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

220. Что такое RAID 1?

   **Ответ:** Зеркало: данные записываются на несколько дисков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

221. Какие плюсы RAID 1?

   **Ответ:** Продолжение работы при отказе части зеркал и возможность распределять чтение.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

222. Какие минусы RAID 1?

   **Ответ:** Полезная ёмкость ограничена размером одной копии для обычного зеркала; запись должна обновлять все рабочие копии.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

223. Что такое RAID 5?

   **Ответ:** Чередование данных с распределённой одной parity; выдерживает отказ одного диска.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

224. Как работает parity в RAID 5?

   **Ответ:** Parity для полосы вычисляется из блоков данных, обычно XOR, и размещается на разных дисках для разных stripes.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

225. Сколько дисков минимум нужно для RAID 5?

   **Ответ:** Минимум три диска; полезная ёмкость для равных дисков примерно `(N-1) × S`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

226. Что такое RAID 6?

   **Ответ:** Массив с двумя независимыми parity-блоками на полосу; выдерживает отказ двух дисков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

227. Чем RAID 6 отличается от RAID 5?

   **Ответ:** Двойная избыточность повышает устойчивость и стоимость записи; минимум обычно четыре диска.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

228. Что такое RAID 10?

   **Ответ:** Чередование поверх зеркал; в типичной схеме — минимум четыре диска и половина суммарной ёмкости.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

229. Чем RAID 10 отличается от RAID 1 и RAID 0?

   **Ответ:** Совмещает параллелизм striping и избыточность зеркал. Linux md поддерживает также специальные RAID10 layouts.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

230. Какой RAID выбирают ради производительности?

   **Ответ:** Для производительности без защиты — RAID0; с защитой часто рассматривают RAID10. Выбор подтверждают измерением нагрузки.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

231. Какой RAID выбирают ради отказоустойчивости?

   **Ответ:** RAID1, RAID6 или RAID10 по требованиям ёмкости и модели отказов; RAID10 не выдерживает любую комбинацию двух отказов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

232. Что такое rebuild RAID?

   **Ответ:** Восстановление недостающей копии/данных на заменённом или резервном диске.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

233. Почему rebuild может быть долгим и рискованным?

   **Ответ:** Читает много данных, конкурирует с рабочей нагрузкой и нагружает оставшиеся диски; в это время запас избыточности уменьшен.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

234. Что происходит при отказе диска в RAID 1?

   **Ответ:** Массив с оставшейся исправной копией продолжает работать в degraded состоянии; требуется заменить диск и восстановить зеркало.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

235. Что происходит при отказе диска в RAID 5?

   **Ответ:** После одного отказа данные восстанавливаются из остальных блоков и parity; следующий отказ до rebuild обычно фатален.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

236. Что такое degraded array?

   **Ответ:** Работающий массив с неполным набором исправных устройств и уменьшенной избыточностью.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

237. Что такое hot spare?

   **Ответ:** Резервное устройство, которое может автоматически включиться в восстановление вместо отказавшего.

   **Пример:** Hot spare не является backup.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

238. Что такое software RAID в Linux?

   **Ответ:** RAID, реализованный программно ядром; распространённый вариант — подсистема md.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

239. Что такое mdadm?

   **Ответ:** Пользовательская утилита создания, сборки, управления и мониторинга md-массивов.

   **Пример:** `cat /proc/mdstat` показывает состояние ядра.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

240. Чем software RAID отличается от hardware RAID?

   **Ответ:** Software RAID управляет ОС, hardware RAID — контроллер с прошивкой, часто представляющий один виртуальный диск.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

241. Какие плюсы у software RAID?

   **Ответ:** Переносимость между контроллерами, прозрачность ОС и отсутствие зависимости от конкретной RAID-платы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

242. Какие плюсы у hardware RAID?

   **Ответ:** Автономное управление массивом и защищённый write-back cache при соответствующем оборудовании.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

243. Какие минусы у hardware RAID?

   **Ответ:** Зависимость от контроллера/формата метаданных, стоимость и возможное сокрытие состояния дисков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

244. Почему RAID не отменяет мониторинг дисков?

   **Ответ:** Массив тоже деградирует, rebuild может сорваться; нужны уведомления, SMART/health и контроль scrubbing.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

245. Что такое write hole?

   **Ответ:** Несогласованность данных и parity после прерванной частичной записи; способы защиты зависят от реализации RAID.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

246. Почему RAID 5/6 может быть чувствителен к write penalty?

   **Ответ:** Мелкие частичные записи требуют читать старые блоки и пересчитывать parity; full-stripe writes уменьшают накладные расходы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

247. Как RAID влияет на latency и throughput?

   **Ответ:** Параллелизм может увеличить throughput, но parity, синхронная запись зеркал и rebuild повышают latency.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

248. Как RAID взаимодействует с файловой системой?

   **Ответ:** ФС видит блочное устройство; согласование stripe geometry и корректное выполнение flush влияют на эффективность и надёжность.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

249. Можно ли поверх RAID использовать LVM?

   **Ответ:** Да, md-устройство может быть PV для LVM.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

250. Почему комбинация RAID + LVM часто встречается в production?

   **Ответ:** RAID обеспечивает выбранную избыточность, LVM — распределение ёмкости; backup и мониторинг нужны отдельно.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man4/md.4.html)

### Practical C/C++ / Linux Filesystem Questions
251. Что происходит на уровне ОС при open() файла?

   **Ответ:** Ядро разрешает путь, проверяет доступ, вызывает операции ФС и создаёт открытое файловое описание, на которое возвращает FD.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/open.2.html)

252. Как VFS участвует в open(), read(), write()?

   **Ответ:** VFS предоставляет единый интерфейс и выбирает операции конкретной ФС; read/write могут обслуживаться page cache.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/open.2.html)

253. Чем stat() отличается от lstat()?

   **Ответ:** `stat()` следует конечной symlink, `lstat()` возвращает метаданные самой ссылки.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/stat.2.html)

254. Как через stat() получить inode number?

   **Ответ:** После успешного `stat(path, &st)` прочитать `st.st_ino`; для FD использовать `fstat()`.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/stat.2.html)

255. Как определить, что два path указывают на один и тот же inode?

   **Ответ:** Сравнить `st_dev` и `st_ino` результатов stat; для защиты от изменения путей предпочтительны открытые FD и fstat.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/stat.2.html)

256. Как через C определить тип файла: regular file, directory, symlink?

   **Ответ:** После `lstat()` проверить `S_ISREG(st.st_mode)`, `S_ISDIR(...)`, `S_ISLNK(...)`; stat следует symlink.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/stat.2.html)

257. Что делает unlink() на уровне файловой системы?

   **Ответ:** Удаляет запись каталога и уменьшает число ссылок; другие имена и открытые FD остаются действительными.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/unlink.2.html)

258. Почему unlink() не всегда сразу освобождает место?

   **Ответ:** Данные удерживают другие hard links, FD или mappings; освобождение происходит после исчезновения последних ссылок.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/unlink.2.html)

259. Что делает rename() внутри одной файловой системы?

   **Ответ:** Атомарно меняет привязки имён в пределах поддерживаемого mount; при замене целевого имени открытые FD старого файла остаются действительными.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/rename.2.html)

260. Почему rename() часто атомарен внутри одной ФС?

   **Ответ:** Изменение видимости имён — единая операция для наблюдателей; это не гарантирует сохранность после сбоя питания.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/rename.2.html)

261. Что произойдет при rename() между разными mount points?

   **Ответ:** `rename()` между разными mounts возвращает `EXDEV`, в том числе для разных mount points одной ФС в Linux.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/rename.2.html)

262. Чем fsync() отличается от fflush()?

   **Ответ:** `fflush()` переносит буфер stdio в ядро; `fsync()` просит синхронизировать данные и необходимые метаданные файла с хранилищем.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

263. Почему fflush() не гарантирует запись на диск?

   **Ответ:** Данные могут остаться в page cache; успешный write/fflush не равен подтверждённой устойчивой записи.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

264. Когда нужно вызывать fsync()?

   **Ответ:** Когда требуется durability, например перед подтверждением сохранения состояния; нужно проверять ошибку самого fsync.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

265. Что делает fdatasync()?

   **Ответ:** Синхронизирует данные и необходимые для их чтения метаданные, например размер; необязательные timestamps могут не синхронизироваться.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

266. Почему crash consistency важна для C/C++ приложений?

   **Ответ:** После сбоя сохранённые структуры должны оставаться допустимыми; нужны протокол записи, синхронизация и восстановление, а не только успешный write.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

267. Что такое atomic file update через temp file + rename()?

   **Ответ:** Создать temp в том же каталоге, записать с обработкой short writes, `fsync(temp)`, `rename(temp,target)`, `fsync(dirfd)`; проверять ошибки всех этапов.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/fsync.2.html)

268. Почему такой паттерн часто используют для конфигов и state files?

   **Ответ:** Читатель видит старую или новую целую версию; durability обеспечивается отдельной синхронизацией файла и каталога.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/rename.2.html)

269. Как mmap() связан с файловой системой?

   **Ответ:** `mmap()` отображает файл в адресное пространство; MAP_SHARED связывает изменения с файлом, MAP_PRIVATE даёт частные COW-страницы.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/mmap.2.html)

270. Когда mmap() удобнее read()/write()?

   **Ответ:** При произвольном доступе и разделении данных; выигрыш зависит от page faults, размера и шаблона доступа.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/mmap.2.html)

271. Какие риски у mmap() при работе с файлами?

   **Ответ:** Усечение файла другим процессом может вызвать SIGBUS; нужны контроль lifetime, размера и синхронизация shared доступа.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/mmap.2.html)

272. Что такое page cache и как он влияет на производительность I/O?

   **Ответ:** Кеш страниц хранит файловые данные в RAM, ускоряет повторные обращения и откладывает запись dirty pages.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/mmap.2.html)

273. Почему последовательное и случайное чтение ведут себя по-разному?

   **Ответ:** Последовательный доступ использует readahead и объединение I/O; случайный чаще вызывает отдельные промахи и обращения к устройству.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/posix_fadvise.2.html)

274. Как приложение может обнаружить “disk full”?

   **Ответ:** Проверять результаты write, fflush, fsync и close: ошибка может проявиться после успешных предыдущих записей.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/write.2.html)

275. Какие errno часто связаны с файловыми операциями?

   **Ответ:** `ENOENT`, `EACCES`, `EPERM`, `ENOSPC`, `EDQUOT`, `EROFS`, `EIO`, `EXDEV`, `EMFILE`, `ENFILE`; контекст определяется вызовом.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/open.2.html)

276. Как обработать ENOSPC?

   **Ответ:** Прекратить неподтверждённые записи, сохранить согласованность, сообщить ошибку и освободить место по политике; бесконечный retry не помогает.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/write.2.html)

277. Как обработать EXDEV при move между ФС?

   **Ответ:** Скопировать во временный файл на целевой ФС, проверить и синхронизировать его, переименовать там, затем удалить исходник. Вся операция не атомарна.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/rename.2.html)

278. Почему важно учитывать inode exhaustion в приложениях, создающих много мелких файлов?

   **Ответ:** Каждый файл расходует inode независимо от размера; ENOSPC может возникнуть задолго до заполнения блоков.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/open.2.html)

279. Как найти открытые удаленные файлы, которые держат место на диске?

   **Ответ:** `lsof +L1`; затем найти владельца FD и организовать корректное закрытие/reopen, учитывая namespace и права доступа.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/unlink.2.html)

280. Какие ошибки работы с ФС чаще всего встречаются в системном C/C++ коде?

   **Ответ:** Игнорирование short writes и ошибок fsync, TOCTOU, утечки FD, предположение об атомарном межфайловом move и небезопасная работа с temp files.

   **Источник:** [Документация](https://man7.org/linux/man-pages/man2/write.2.html)
